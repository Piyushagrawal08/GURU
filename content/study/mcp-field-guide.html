Study notes · Model Context Protocol · spec 2026-07-28

MCP Field Guide

One document that takes you from "what is MCP?" to building your own MCP server, plugging it into Claude and LangChain, and running it safely. Every chapter has a plain explanation, and most have an example you can follow.

How to read this

Parts I and II explain the ideas: read them in order. Part III builds one small server, step by step. Parts IV and V show how to use and run it. Chapters marked with a green dot in the contents have Example boxes.

The examples use one running example: a Plant TAT server that lets an AI look up truck turnaround times (TAT) at a factory. The numbers are made up so you can run it anywhere.

Chapter 1 · Foundations

What is MCP?

MCPModel Context Protocol · open standard

An open standard that lets AI applications connect to outside tools and data in one common way. You build a connector once, as an MCP server, and any AI app that speaks MCP can use it: Claude, ChatGPT, VS Code, Cursor, LangChain agents and many more.

Anthropic released MCP in November 2024. It is now an open project with its own specification, official SDKs in many languages, and thousands of servers. The latest version of the specification is dated 2026-07-28.

The usual comparison is USB-C for AI. Before USB-C, every device had its own cable. Now one port fits many devices. MCP does the same for AI apps and the systems they need to reach.

Example

Without MCP vs with MCP

Without MCP, every AI app needs its own custom code for every system. With MCP, each system gets one server, and every app plugs into it the same way.

Example

ClientThe port inside the deviceOne connection from the host to one server

Easy definition

MCP is a standard way to give an AI app new abilities. Write the connector once, use it in every MCP-compatible app.

Chapter 2 · Foundations

The problem MCP solves

An AI model on its own only knows what it learned in training. To be useful at work it must reach your systems: databases, files, ticketing tools, chat. Before MCP, each AI app built its own connectors, so the same integration was written again and again.

Example

From N × M integrations to N + M

Three AI apps and three systems need nine custom integrations. With MCP, each app supports MCP once and each system gets one server: six pieces in total, and adding a fourth app costs one piece, not three.

ProblemWithout MCPWith MCP
Repeated workEvery app rebuilds the same connectorBuild one server, reuse it everywhere
Switching AI appsRewrite your integrationsPoint the new app at the same servers
DiscoveryThe app must be told about each function in codeThe app asks the server "what can you do?" at run time
OwnershipThe AI team owns every integrationThe team that owns a system can publish its server
Chapter 3 · Foundations

Where to use MCP (and where not to)

Company data for AI assistants

Let Claude or an internal copilot look up orders, vehicles, stock or tickets.

Developer tools

Give coding assistants access to GitHub, databases, logs and docs.

One integration, many apps

The same server works in Claude Desktop, Claude Code, VS Code and your own agents.

Products offering AI access

SaaS companies publish a remote MCP server so customers' AI tools can use their product.

When something else fits better

One app, one function

If only your own agent needs one small function, a plain tool inside the agent is simpler (see the LangChain guide's Tools chapter).

Fixed data pipelines

Nightly reports or ETL jobs don't need an AI to decide anything. Use normal scripts and schedulers.

Chapter 4 · Foundations

Host, client, server

MCP has three roles. Learn these three words and the rest of MCP is easy to follow.

RoleWhat it isExamples
HostThe AI application the user works in. It contains the LLM and decides what to connect to.Claude Desktop, Claude Code, VS Code, your LangChain app
ClientA connector inside the host. Each client talks to exactly one server.Created automatically by the host
ServerA program that offers tools, resources and prompts. It does the real work against a system.Plant TAT server, GitHub server, filesystem server
Example

One host, two servers

Claude Desktop (the host) connects to our local Plant TAT server and to a remote GitHub server. It creates one client for each.

MCP does not include the AI model

A server has no LLM inside it. It only offers abilities. The host's model decides when to use them. That is why the same server works with Claude, GPT or any other model.

Chapter 5 · How it works

Tools, resources and prompts

A server can offer three kinds of things. The difference is who decides to use them.

TypeWhat it isWho decides to use itReal-world comparison
ToolAn action the AI can run, such as "look up TAT" or "create ticket"The model (the host should let the user approve)A button the AI presses
ResourceRead-only data with an address (URI), such as a file or a tableThe app (or the user picks it to attach)A document handed to the AI
PromptA ready-made request templateThe user (picks it from a menu or slash command)A saved question you reuse
Example

What the Plant TAT server offers

tool get_plant_tat

Returns the plant TAT for a date, with the target. The AI calls it when someone asks "how was TAT yesterday?"

tool get_stage_delays

Returns minutes over target for each stage: loading, documentation, weighbridge, gate.

resource tat://targets

The target minutes per stage. The user can attach it so the AI knows the goals.

prompt explain_delay

A saved request: "Explain why plant TAT was high on {date}." The user picks it and types a date.

You will build exactly this server in Chapter 10.

Beginners: start with tools

Most hosts support tools best, and many servers offer only tools. Add resources and prompts once your tools work.

Chapter 6 · How it works

When the server needs to ask the user

Sometimes a server needs more information halfway through a task, or a confirmation. MCP calls this elicitation. The server asks; the host shows the question to the user; the answer goes back to the server.

Example

Confirming before sending a delay alert

The AI asks a server to send a delay alert to a transport company, but the server needs a contact person first.

  1. AI → server: "Call send_delay_alert for FastFreight."
  2. Server → host: "I need more input: which contact person should receive it?" (the server does not finish yet)
  3. Host → user: shows a small form with the question.
  4. User: types "Ravi Kumar" and confirms, or cancels.
  5. Host → server: repeats the original call, now including the answer. The server sends the alert and returns the result.

In the 2026-07-28 version of MCP, this works as "multi round-trip requests": the server replies "input required", and the client asks again with the answer. SDKs handle this for you.

Client featureWhat it doesStatus in spec 2026-07-28
ElicitationServer asks the user for information or confirmationactive
SamplingServer asks the host's LLM to write somethingdeprecated call an LLM provider directly instead
RootsHost tells the server which folders matterdeprecated pass folders as tool arguments or config

"Deprecated" means it still works for at least twelve months but new servers should not depend on it. Older tutorials teach sampling and roots as core features; that advice is now out of date.

Chapter 7 · How it works

Transports: stdio and HTTP

A transport is how messages travel between client and server. There are two standard ones.

Example

Local vs remote

stdioStreamable HTTP
Where the server runsOn your computer, started by the hostOn a server or in the cloud
Who can use itOnly youAnyone you give access to
Sign-inNot needed (uses your own computer's access)Needed: OAuth or an API token (Ch. 17)
Best forLearning, personal tools, local filesTeam and company servers, SaaS products
Old name: SSE

Older guides mention an "HTTP + SSE" transport. It has been deprecated since 2025 and replaced by Streamable HTTP. Use Streamable HTTP for anything new.

Chapter 8 · How it works

How messages flow

Client and server exchange small JSON messages in a format called JSON-RPC: a request with a method name and an ID, and a response with the same ID. You will rarely write these by hand, because the SDK does it, but seeing them once makes everything clearer.

Example

"How was plant TAT on 5 October?"

Step 5 and step 6 on the wire look like this:

client → server: tools/call
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "get_plant_tat",
    "arguments": { "date": "2026-10-05" }
  }
}
server → client: result
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "resultType": "complete",
    "content": [
      { "type": "text", "text": "2026-10-05: plant TAT 192 min, target 142 min." }
    ],
    "isError": false
  }
}

Every request also carries a small _meta block (protocol version, client name and capabilities). It is left out above to keep the example short.

What changed in 2026-07-28

Earlier versions started every connection with an initialize handshake and kept a session open. The 2026-07-28 version is stateless: each request carries its own version and capabilities, so any server copy can answer it. A new server/discover call lets a client ask a server what it supports. Current SDKs talk to both old and new servers automatically.

MethodMeaning
server/discover"Which versions and features do you support?"
tools/list · tools/callList the tools · run one tool
resources/list · resources/readList the data · read one item
prompts/list · prompts/getList the templates · fill one in

Errors come in two kinds. A protocol error (unknown tool, bad request) is a JSON-RPC error. A tool error (wrong date format, database down) is a normal result with "isError": true and a message, so the AI can read it and try again.

Chapter 9 · Build a server

Install and set up

  1. Python 3.10 or newer. Check with python --version.
  2. A project folder and a virtual environment, so packages stay separate.
  3. Install the MCP Python SDK with its command-line extras.
  4. Node.js 22.19 or newer (optional) to run the MCP Inspector test tool in Chapter 11.
terminal (Windows PowerShell)
mkdir mcp-tat
cd mcp-tat
python -m venv .venv
.venv\Scripts\Activate.ps1          # macOS/Linux: source .venv/bin/activate

pip install -U "mcp[cli]"
Older tutorials use a different name

The Python SDK version 2 renamed FastMCP to MCPServer. If a tutorial says from mcp.server.fastmcp import FastMCP, it was written for version 1. With the current SDK, use from mcp.server import MCPServer. The decorators (@mcp.tool() and so on) work the same way.

Official SDKs also exist for TypeScript, Java, Kotlin, C#, Go, Ruby, Rust, Swift and PHP. The ideas in this guide apply to all of them.

Chapter 10 · Build a server

Your first server

A server is a normal Python file. You write ordinary functions and add a decorator to each one. The SDK turns them into MCP tools, resources and prompts: it reads the function name, the type hints and the docstring, and builds the description the AI sees.

Example

The Plant TAT server

Two tools, one resource, one prompt. Save it as tat_server.py.

tat_server.py
from mcp.server import MCPServer

mcp = MCPServer("Plant TAT")

# Sample data. In real life this comes from your database.
STAGE_MINUTES = {"loading": 81, "documentation": 63, "weighbridge": 34, "gate_entry": 14}
TARGET_MINUTES = {"loading": 60, "documentation": 48, "weighbridge": 24, "gate_entry": 10}


@mcp.tool()
def get_plant_tat(date: str) -> str:
    """Get the average plant TAT for a date (YYYY-MM-DD), compared with the target."""
    actual = sum(STAGE_MINUTES.values())
    target = sum(TARGET_MINUTES.values())
    return f"{date}: plant TAT {actual} min, target {target} min."


@mcp.tool()
def get_stage_delays(date: str) -> dict:
    """Minutes over target for each plant stage on a date (YYYY-MM-DD)."""
    return {s: STAGE_MINUTES[s] - TARGET_MINUTES[s] for s in STAGE_MINUTES}


@mcp.resource("tat://targets")
def tat_targets() -> str:
    """The plant's target minutes for each stage."""
    return str(TARGET_MINUTES)


@mcp.prompt()
def explain_delay(date: str) -> str:
    """A ready-made request: explain why TAT was high on a date."""
    return f"Use the TAT tools to explain why plant TAT was high on {date}. Name the worst stage."


if __name__ == "__main__":
    mcp.run()          # default transport: stdio
LineWhat it does
MCPServer("Plant TAT")Creates the server and gives it a name hosts will show
@mcp.tool()Turns the function below into a tool the AI can call
The docstring """Get the average…"""Becomes the tool description. The AI reads it to decide when to use the tool, so write it clearly
date: strBecomes the tool's input: one text field called "date"
@mcp.resource("tat://targets")Publishes read-only data at that address
@mcp.prompt()Publishes a ready-made request the user can pick
mcp.run()Starts the server, talking over stdio

If you run python tat_server.py, nothing seems to happen. That is correct: a stdio server waits silently for a host to talk to it. Stop it with Ctrl+C. The next chapter shows how to test it.

Never print() in a stdio server

In a stdio server, the output channel carries the MCP messages. A stray print() mixes ordinary text into them and breaks the connection. Log to stderr instead: print("debug", file=sys.stderr).

Chapter 11 · Build a server

Test it

Test your server before connecting it to an AI. Then, if something goes wrong later, you know the server itself works.

Example

Option A: the MCP Inspector (a test screen in your browser)

The Inspector is the official testing tool. It starts your server, shows its tools, resources and prompts, and lets you run each one by filling in a form. It needs Node.js but no install.

terminal
# Opens a browser page connected to your server
npx @modelcontextprotocol/inspector python tat_server.py

# Or run one tool from the command line, no browser
npx @modelcontextprotocol/inspector --cli python tat_server.py --method tools/call --tool-name get_plant_tat --tool-arg date=2026-10-05
{ "content": [ { "type": "text", "text": "2026-10-05: plant TAT 192 min, target 142 min." } ], "structuredContent": { "result": "2026-10-05: plant TAT 192 min, target 142 min." }, "isError": false }
Example

Option B: a tiny Python client

This script plays the part of a host: it starts the server, asks what tools it has, and calls one. Put it in the same folder.

tat_client.py
import asyncio, sys
from mcp import Client, StdioServerParameters

server = StdioServerParameters(command=sys.executable, args=["tat_server.py"])

async def main():
    async with Client(server) as client:
        tools = await client.list_tools()
        print("Tools:", [t.name for t in tools.tools])

        result = await client.call_tool("get_plant_tat", {"date": "2026-10-05"})
        print("Result:", result.content[0].text)

asyncio.run(main())
Tools: ['get_plant_tat', 'get_stage_delays'] Result: 2026-10-05: plant TAT 192 min, target 142 min.
Chapter 12 · Use servers

Connect to Claude Desktop and Claude Code

Once the server works, tell a host where to find it. The host then starts it and offers its tools to the model.

Example

Claude Desktop

Open Settings → Developer → Edit Config. This opens claude_desktop_config.json (on Windows: %APPDATA%\Claude\claude_desktop_config.json). Add your server, save, and fully restart Claude Desktop.

claude_desktop_config.json
{
  "mcpServers": {
    "plant-tat": {
      "command": "C:\\Users\\you\\mcp-tat\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\you\\mcp-tat\\tat_server.py"]
    }
  }
}

Use full paths: Claude Desktop does not start in your project folder. Pointing at the virtual environment's python.exe makes sure the mcp package is found. Then ask Claude "How was plant TAT on 5 October 2026?" and approve the tool call when it asks.

Example

Claude Code

One command adds the server. Everything after -- is the command that starts it.

terminal
# Local server (stdio)
claude mcp add --transport stdio plant-tat -- python C:\Users\you\mcp-tat\tat_server.py

# Remote server (HTTP), e.g. Notion
claude mcp add --transport http notion https://mcp.notion.com/mcp

claude mcp list            # see all servers
claude mcp remove notion   # remove one
# Inside Claude Code, type /mcp to check status or sign in
Scope (--scope)Who gets the server
local (default)Only you, only in this project
projectEveryone on the project: it is saved in a shared .mcp.json file
userOnly you, in all your projects
Remote servers in claude.ai

For remote (HTTP) servers, Claude's apps also offer Connectors in settings: paste the server's URL and sign in. No config file needed.

Chapter 13 · Use servers

Use MCP servers from LangChain

A LangChain agent can use any MCP server's tools as if they were its own. LangChain 1.4 and later include this as langchain.mcp (beta). This matches Chapter 20 of the LangChain v1 Field Guide.

Example

A LangChain agent using the Plant TAT server

tat_agent.py
# pip install -U "langchain[mcp]" langchain-anthropic
import asyncio
from pathlib import Path
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter

async def main():
    async with MCPAdapter(Path("tat_server.py")) as adapter:   # starts the server
        tools = await adapter.list_tools()      # get_plant_tat, get_stage_delays
        agent = create_agent("anthropic:claude-sonnet-4-6", tools)
        result = await agent.ainvoke({"messages": [
            {"role": "user", "content": "Why was plant TAT high on 2026-10-05?"}
        ]})
        print(result["messages"][-1].text)

asyncio.run(main())
# example output: the model's wording will differ Plant TAT on 2026-10-05 was 192 minutes against a 142 minute target. Loading was the biggest problem: 21 minutes over target, followed by documentation at 15 minutes over.

MCPAdapter also accepts a URL for a remote server, or a config with several servers: {"mcpServers": {"tat": {...}, "github": {"url": "..."}}}. With several servers, tool names get the server name in front (for example tat_get_plant_tat).

Chapter 14 · Use servers

Use MCP servers from the Claude API

If you call Claude through the API, you can pass a remote MCP server in the request. Anthropic's side connects to the server and runs the tools. You don't write any client code.

Example

The MCP connector

api_mcp.py
import anthropic

client = anthropic.Anthropic()

response = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": "How was plant TAT on 2026-10-05?"}],
    mcp_servers=[{
        "type": "url",
        "url": "https://tat.example.com/mcp",     # must be reachable from the internet
        "name": "plant-tat",
        "authorization_token": "YOUR_TOKEN",       # if the server needs sign-in
    }],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "plant-tat"}],
    betas=["mcp-client-2025-11-20"],
)
print(response.content[-1].text)
Limits

This is a beta feature. It only supports tools (not resources or prompts), and only remote HTTP servers. A local stdio server on your laptop cannot be reached this way: use LangChain or the Python Client instead.

Chapter 16 · Production

Remote servers

A local server serves one person. To share the Plant TAT server with your whole team, or with Claude through the API, run it as a remote server over Streamable HTTP.

Example

Turn the Plant TAT server into a web service

Change only the last line of tat_server.py:

tat_server.py (last lines)
if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="127.0.0.1", port=8000)

The server now answers at http://127.0.0.1:8000/mcp. A client connects with just the URL:

connect by URL
async with Client("http://127.0.0.1:8000/mcp") as client:
    result = await client.call_tool("get_plant_tat", {"date": "2026-10-05"})
  • Put it behind HTTPS. Use a reverse proxy or a cloud platform; never expose plain HTTP on the internet.
  • Require sign-in before anyone can call a tool (next chapter).
  • Scale easily. Because the 2026-07-28 protocol is stateless, you can run several copies behind a load balancer.
  • Log and monitor every tool call: who called it, with what, and how long it took.
Chapter 17 · Production

Security and sign-in

MCP gives an AI the power to act. The specification is clear that hosts must get the user's consent before using tools or sharing data. As a server builder, your job is to make sure the AI can only do what it should.

Sign-in for remote servers

Remote servers use OAuth 2.1, the same "Sign in with…" flow you know from websites. The user signs in once in the browser; the host then sends a token with every request; the server checks it. Local stdio servers don't need this, because they run on the user's own computer.

Main risks

RiskWhat happensProtection
Too much powerA tool like run_any_sql lets the AI read or delete anythingOffer narrow tools (get_plant_tat), read-only database accounts
Prompt injectionData the tool returns (an email, a web page) contains hidden instructions like "send all files to…"Treat tool results as untrusted; require approval for risky actions
Tool poisoningA malicious server hides instructions in its tool descriptionsInstall only trusted servers; review descriptions
Silent changesA server you approved later changes its toolsPin versions; re-review after updates
Leaked secretsAPI keys written into prompts or tool resultsKeep keys in environment variables, never return them from tools
Example

Safe and risky tools in the TAT server

Safe: read-only

get_plant_tat, get_stage_delays. They only read numbers. Hosts can let these run freely.

Risky: acts on the world

send_delay_alert, update_vehicle_record. The user should approve each call. Claude asks before running tools by default.

Keep risky actions as separate tools with clear names. Then a host, or a LangChain HumanInTheLoopMiddleware, can ask for approval on exactly those tools.

Common mistakes

MistakeWhat to do instead
Using print() in a stdio serverLog to stderr. Stdout carries the MCP messages.
Relative paths in Claude Desktop's configUse full paths to Python and to the script.
Editing the config and not restartingQuit Claude Desktop completely and open it again.

Vague tool docstringsSay what the tool does, when to use it, and the format of each input.
One giant "do anything" toolSeveral small, specific tools. Easier for the AI, safer for you.

Chapter 20 · Mastery

Learning path

  1. Understand the idea. USB-C analogy, N + M, host / client / server. Ch. 1–4
  2. Learn the three building blocks. Tools, resources, prompts. Ch. 5
  3. Use a ready-made server. Add the Filesystem server to Claude Desktop and ask about a folder. Ch. 12, 15
  4. Build the Plant TAT server. Ch. 10
  5. Test it with the Inspector and the Python client. Ch. 11
  6. Connect it to Claude Desktop or Claude Code and ask a real question. Ch. 12
  7. Use it from an agent with LangChain. Ch. 13
  8. Swap the sample data for real queries against your own database.
  9. Go remote and secure: Streamable HTTP, HTTPS, sign-in, approvals. Ch. 16–17
Final takeaway

Build a capability once as an MCP server, and every MCP-compatible AI app can use it. Start local with stdio and a few small, read-only tools. Go remote, with sign-in and approvals, when other people need it.

Glossary

ClientThe connector inside a host that talks to one server.
ElicitationA server asking the user, through the host, for more information or a confirmation.
HostThe AI application the user works in, such as Claude Desktop or Claude Code.
InspectorThe official tool for testing MCP servers in a browser or terminal.
JSON-RPCThe simple request/response message format MCP uses.
OAuthThe standard "sign in with…" method remote servers use to check who is calling.
PromptA ready-made request template a server offers to users.
ResourceRead-only data a server offers at an address (URI).
SDKA code library that handles the protocol for you, such as the mcp Python package.
ServerA program that offers tools, resources and prompts over MCP.
stdioLocal transport: the host starts the server and talks through its input and output.
Streamable HTTPRemote transport: the host sends HTTPS requests to the server's /mcp address.
TATTurnaround time: how long a vehicle spends inside the plant. Used in this guide's examples.
ToolAn action a server offers, which the model can decide to call.
