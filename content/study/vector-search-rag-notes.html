    1. Vector Embeddings

    Embeddings turn text, images and audio into lists of numbers so a computer can measure "how similar in meaning" two things are. Everything else in a RAG system depends on this step.

    1.1

    Vector

    A list of numbers representing content such as text, image, audio, or video.

    What is it?

    A vector is an ordered list of numbers, for example [0.12, -0.48, 0.91]. Each number is a coordinate, so the whole vector is a point in a space. In AI systems, a vector is a numeric "fingerprint" of a piece of content.

    Vectors exist because computers cannot compare meaning directly, but they can compare numbers very quickly.

    GPS coordinates for meaning. Two cafés on the same street have nearby coordinates. Two sentences that mean nearly the same thing get nearby vectors.

    Why is it important?

    • Every later step (similarity, indexing, the vector database, retrieval) works on vectors, not on raw text.
    • If the vectors are built from bad text or from mixed models, the "distances" between them stop meaning anything and search returns nonsense.

    Where is it used?

    • Semantic search over PDFs and wikis
    • RAG chatbots
    • Image search ("find similar products")
    • Recommendations (songs, articles)
    • Duplicate and near-duplicate detection

    How does it work?

    1. Raw content goes into an embedding model.
    2. The model outputs a fixed-length list of floats.
    3. You store the list (usually as float32, 4 bytes per number) with an ID that points back to the source text.

    Example

    import numpy as np
refund   = np.array([0.81, 0.10, 0.05])   # "How do I get a refund?"
money_bk = np.array([0.78, 0.15, 0.02])   # "Can I get my money back?"
weather  = np.array([0.02, 0.05, 0.93])   # "Will it rain tomorrow?"
print(np.linalg.norm(refund - money_bk))  # 0.07  (close)
print(np.linalg.norm(refund - weather))   # 1.16  (far)

    Diagram

     |   * "refund policy"
     |  * "get my money back"

  Close points = similar meaning (real vectors have hundreds of dimensions)

    Common mistakes

    • Trying to read meaning into a single dimension. Individual numbers are not human-interpretable.
    • Storing vectors as float64, which doubles memory for no quality gain.
    • Losing the link from vector back to its source text and page.

    Best practices

    • Use float32 NumPy arrays.
    • Always store an ID plus source text and metadata next to each vector.

    Interview questions

    1. What is a vector in the context of AI search?A fixed-length list of numbers that represents content so similarity can be computed mathematically.
    2. Why not search raw text directly?Raw text matching only finds exact words; vectors let you compare meaning, including synonyms and paraphrases.
    3. How much memory does one 768-dim float32 vector take?768 × 4 bytes = 3,072 bytes, about 3 KB.
    4. Can you interpret dimension 42 of an embedding?Generally no. Meaning is spread across all dimensions together.
    5. What must you store alongside a vector?A stable ID, the original text (or a pointer to it) and metadata such as source file and page.

    Dimension

    The length of a vector. Example: a 768-dimensional embedding contains 768 numbers.

    What is it?

    The dimension is how many numbers are in each vector. It is fixed by the embedding model: every vector from the same model has the same length.

    A form with 768 boxes. More boxes let you describe something in more detail, but every form takes more paper to store.

    Why is it important?

    • Your index and database column are created for one dimension. Insert a 1536-dim vector into a 768-dim collection and you get a dimension-mismatch error.
    • Dimension drives memory, storage and search speed.

    How does it work? Common sizes

    ModelDimensionMemory for 1M vectors (float32)
    all-MiniLM-L6-v2384≈ 1.5 GB
    BAAI/bge-base-en-v1.5, all-mpnet-base-v2768≈ 3.1 GB
    OpenAI text-embedding-3-small1536≈ 6.1 GB
    OpenAI text-embedding-3-large3072≈ 12.3 GB

    Formula: memory ≈ N × d × 4 bytes (plus index overhead).

    Trade-off: higher dimension can capture more nuance, but returns diminish and cost grows linearly. Some models (Matryoshka-trained, including OpenAI's text-embedding-3 family via the dimensions parameter) let you shorten vectors with a small quality loss.

    Example

    from sentence_transformers import SentenceTransformer
m = SentenceTransformer("all-MiniLM-L6-v2")
v = m.encode("Refunds are processed within 5 days.")
print(v.shape)   # (384,)

    Common mistakes

    • Switching models without recreating the collection.
    • Assuming a bigger dimension always means better retrieval.

    Best practices

    • Do the memory math before choosing a model.
    • Record the dimension in your collection config and versioning notes.

    Interview questions

    1. What determines embedding dimension?The model architecture; you cannot choose it freely except with models that support truncation.
    2. Estimate RAM for 10M 768-dim vectors.10M × 768 × 4 ≈ 30.7 GB raw, before index overhead.
    3. Is 3072 always better than 768?No. Test on your own data; a well-matched smaller model often wins and is cheaper.
    4. How can you reduce memory without changing models?Quantization, or dimension truncation for Matryoshka-style models.
    5. What happens if query and index dimensions differ?The search fails with an error; if they match by coincidence but come from different models, results are silently wrong.

    References

    • OpenAI – Embeddings guide (dimensions parameter)
    • Matryoshka Representation Learning (paper)

    Embedding model

    Converts raw content into a dense numeric vector that captures meaning.

    What is it?

    A neural network (usually a transformer encoder) trained so that content with similar meaning produces vectors that are close together. It is the "translator" from human content to numbers.

    A librarian who has read millions of books and can place any new page on a giant map, right next to pages about the same subject.

    Why is it important?

    It sets the ceiling for retrieval quality. A model that doesn't understand your domain (legal, medical, code) will place unrelated chunks near each other, and no index or reranker can fully fix that.

    Where is it used?

    At ingestion time (embedding every chunk) and at query time (embedding the user question). Popular options:

    TypeExamplesGood for
    Open source, localall-MiniLM-L6-v2, BAAI/bge-base-en-v1.5, intfloat/e5-base-v2, nomic-embed-textPrivacy, no per-call cost, learning
    Hosted APIOpenAI text-embedding-3-small/large, Cohere Embed, Voyage AIQuick start, strong quality, no GPU needed
    Multilingualbge-m3, multilingual-e5Mixed-language document sets

    When should I use which?

    • Start with a small, fast model (MiniLM or bge-small) to build the pipeline.
    • Shortlist models from the MTEB leaderboard, then pick using your evaluation set.
    • Use an API when you can't host models; use local models when data must not leave your servers.

    How does it work?

    %%{init: {'theme':'default'}}%%
flowchart LR
  T["Text chunk"] --> K["Tokenizer: text to token IDs"]
  K --> E["Transformer encoder"]
  E --> P["Pooling: mean or CLS token"]
  P --> N["Normalize to unit length"]
  N --> V["Vector, e.g. 768 floats"]
    • Bi-encoder: query and document are embedded separately, so documents can be embedded once in advance. This is what embedding models are.
    • Contrastive training: the model is shown (question, correct passage) pairs and learns to pull them together and push wrong passages apart.
    • Asymmetric prefixes: some models expect "query: " / "passage: " (E5) or an instruction on the query (BGE). Skipping them lowers quality.

    Example

    from sentence_transformers import SentenceTransformer
model = SentenceTransformer("BAAI/bge-base-en-v1.5")
chunks = ["Employees get 20 days of paid leave.", "The VPN requires MFA."]
doc_vecs = model.encode(chunks, normalize_embeddings=True, batch_size=32)
q_vec = model.encode("Represent this sentence for searching relevant passages: how many vacation days?",
                     normalize_embeddings=True)
print(doc_vecs @ q_vec)   # higher score for the leave-policy chunk

    Common mistakes

    • Picking the #1 leaderboard model without testing on your documents.
    • Forgetting query/passage prefixes.
    • Embedding one text per API call instead of batching.

    Best practices

    • Batch requests; cache embeddings by content hash.
    • Pin the exact model name and version.
    • Consider fine-tuning only after a baseline evaluation shows a domain gap.

    Interview questions

    1. Bi-encoder vs cross-encoder?Bi-encoders embed texts separately (fast, indexable); cross-encoders read query and document together (accurate, slow), so they are used for reranking.
    2. How do you choose an embedding model?Shortlist by language, domain, max tokens, dimension, cost and license; then compare Recall@k on your own evaluation set.
    3. What is pooling?Combining per-token outputs into one vector, typically by averaging (mean pooling) or using the CLS token.
    4. Why might you fine-tune an embedding model?When domain vocabulary (e.g. internal product codes, legal terms) is poorly represented and evaluation shows retrieval gaps.
    5. What is asymmetric search?Short queries vs long passages; models handle it with separate prefixes or instructions for each side.

    Dense vector

    Most values are non-zero; captures semantic meaning.

    What is it?

    A compact vector (hundreds to a few thousand dimensions) where almost every value is a non-zero float. Produced by neural embedding models.

    A paint colour mixed from many pigments. Every pigment contributes a little, and similar colours have similar mixes.

    Why is it important?

    Dense vectors understand paraphrase: "car" and "automobile", or "cancel my plan" and "end subscription", land close together even with zero shared words.

    When should I use it?

    • Natural-language questions over documents.
    • Weak spot: exact identifiers such as error codes (E-4012), SKUs, names and rare acronyms. Pair with sparse/keyword search (hybrid) for these.

    Example

    dense = [0.021, -0.113, 0.087, 0.004, -0.056, ...]   # 768 values, nearly all non-zero

    Interview questions

    1. Why are dense vectors good at synonyms?They were trained so that texts used in similar contexts get similar vectors, regardless of exact wording.
    2. Where do dense vectors fail?Exact-match needs: IDs, codes, rare names, numbers.
    3. Typical dimension range?About 384 to 3072.
    4. How are dense vectors searched at scale?With ANN indexes such as HNSW or IVF.
    5. Can a dense vector be "explained"?Not directly; that is a reason to keep a keyword channel for debuggable matches.
    1.5

    Sparse vector

    Most values are zero; often reflects keyword or term-frequency signals.

    What is it?

    A very long vector (one slot per vocabulary word, often 30,000+) where almost all values are zero. Only the words present in the text get a weight. Stored as {term_id: weight} to save space.

    A book's index at the back: thousands of possible words, but each page only appears under a handful of them.

    Where is it used?

    • Classic keyword search: TF-IDF and BM25 (Elasticsearch, OpenSearch, Postgres full-text).
    • Learned sparse models such as SPLADE, which add related terms with weights.
    • The keyword half of hybrid search.

    Example

    text   = "reset password error E-4012"
sparse = {"reset": 1.2, "password": 1.8, "error": 0.6, "e-4012": 4.7}   # every other term = 0
    AspectDense vectorSparse vector
    Size384–3072 dims, all filledVocabulary-size dims, mostly zero
    CapturesMeaning, synonyms, paraphraseExact terms and their importance
    Strong at"How do I get my money back?""Error E-4012", "Form W-9", names
    Weak atRare IDs, exact codesSynonyms, different wording
    ExplainableHardEasy (which words matched)
    Typical toolsSentence-Transformers, OpenAI, FAISS, Chroma, pgvectorBM25, Elasticsearch, OpenSearch, SPLADE

    Interview questions

    1. What is BM25?A keyword ranking function that scores documents by term frequency, inverse document frequency and document length normalization.
    2. Why combine dense and sparse?They fail on different queries; hybrid search covers both meaning and exact terms.
    3. What is SPLADE?A neural model that outputs sparse vectors, adding weighted expansion terms while staying index-friendly.
    4. How are sparse vectors stored efficiently?As inverted indexes or index/value pairs, not as full arrays.
    5. Which handles a typo better?Dense usually does; pure keyword matching misses misspelled terms unless fuzzy matching is added.

    Semantic search

    Retrieves results based on meaning rather than exact keyword matching.

    What is it?

    Search where the query and documents are both embedded, and results are the documents whose vectors are closest to the query vector.

    Asking a knowledgeable colleague instead of using Ctrl+F. They understand what you mean even if you use different words from the document.

    Why is it important?

    Users rarely phrase questions with the same words the document uses. Without semantic search, "How do I get my money back?" never finds the page titled "Refund policy".

    Where is it used?

    • Internal knowledge-base search and HR/IT helpdesk bots
    • Customer-support article suggestions
    • The retrieval step of every RAG chatbot

    How does it work?

    %%{init: {'theme':'default'}}%%
flowchart LR
  subgraph Offline
    D["PDF chunks"] --> E1["Embed"] --> I["Vector index"]
  end
  Q["User question"] --> E2["Embed with same model"] --> S["Find nearest vectors"]
  I --> S --> R["Top-k chunks"]

    Example

    Query: "Can I work from another country?" → top result: "Remote work outside the home country requires HR approval for stays over 30 days." (no shared keywords besides "work").

    Common mistakes

    • Expecting it to match exact codes and IDs reliably.
    • Always returning results, even when nothing relevant exists. Consider a score threshold or an "I don't know" path.

    Best practices

    • Combine with keyword search (hybrid) for production.
    • Show sources so users can verify.

    Interview questions

    1. Semantic vs lexical search?Semantic compares meaning via vectors; lexical compares literal terms.
    2. Why must the query use the same model as the documents?Vectors from different models live in different spaces and cannot be compared.
    3. How do you handle "no good answer"?Use a similarity threshold, reranker scores, or let the LLM say the context lacks the answer.
    4. Name a case where semantic search loses to keyword search.Searching for a part number or an exact error code.
    5. What is the output of semantic search?A ranked list of IDs with similarity scores (top-k).

    Token limit

    Every embedding model has a maximum input length; chunks must fit within it.

    What is it?

    The largest number of tokens (word pieces) an embedding model will read. A token is roughly ¾ of an English word, or about 4 characters.

    A scanner tray that fits only one page. Feed it three pages stacked together and only the first is scanned.

    Why is it important?

    Text past the limit is silently truncated by many libraries (Sentence-Transformers does this) or rejected with an error by APIs. Truncated chunks lose their ending, so facts in the second half become unsearchable.

    ModelMax input (tokens)
    all-MiniLM-L6-v2256 (trained on 128)
    bge-base-en-v1.5512
    OpenAI text-embedding-3-small / large8,191

    Example: counting tokens

    from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("BAAI/bge-base-en-v1.5")
n = len(tok.encode(chunk_text))
if n > 512:
    print("Chunk too long, will be truncated:", n)

    Common mistakes

    • Measuring chunk size in characters or words and assuming it fits.
    • Using a long-context model and creating huge chunks just because it allows them.

    Best practices

    • Count tokens with the model's own tokenizer.
    • Keep chunks well under the limit; a limit is not a target.

    Interview questions

    1. What happens when a chunk exceeds the token limit?It is truncated or rejected; either way content is lost from the index.
    2. Rough characters-per-token for English?About 4.
    3. Why not just use 8k-token chunks?Large chunks dilute meaning and waste LLM context; retrieval precision drops.
    4. Embedding token limit vs LLM context window?The first limits one chunk being embedded; the second limits everything sent to the LLM in one request.
    5. How do you enforce the limit in a pipeline?Use a token-based splitter and assert token counts before embedding.

    Model consistency

    Use the same embedding model for indexing and querying. Changing models requires re-embedding the corpus.

    What is it?

    The rule that document vectors and query vectors must come from the same model, same version and same preprocessing (prefixes, normalization).

    Two maps must use the same coordinate system. Plotting a London address on a map of Tokyo gives a point, but it's meaningless.

    Why is it important?

    Different models create different spaces. Even if two models both output 768 numbers, the numbers mean different things. Mixing them gives random-looking results with no error message.

    How does it work?

    %%{init: {'theme':'default'}}%%
flowchart LR
  A["Corpus embedded with Model A v1"] --> IDX["Index A"]
  Q1["Query embedded with Model A v1"] --> IDX
  Q2["Query embedded with Model B"] -. wrong space .-> IDX
  B["Switch to Model B"] --> R["Re-embed whole corpus into Index B"] --> SW["Swap traffic when evaluated"]

    Best practices

    • Store embedding_model and version in collection metadata and check it at query time.
    • When upgrading, build a new index in parallel (blue-green), evaluate, then switch.

    Interview questions

    1. You switched embedding models and quality collapsed. Why?Old document vectors were not re-embedded; queries and documents are now in different spaces.
    2. Can two models with the same dimension share an index?No; equal length does not mean the same space.
    3. How do you upgrade models with zero downtime?Re-embed into a new index, evaluate, then flip an alias.
    4. What else must stay consistent besides the model name?Model version, prefixes/instructions, normalization and text preprocessing.
    5. How do you prevent accidental mixing?Store model ID per collection and validate it in the query service.

    Multimodal embeddings

    Can represent text, images, audio, or combined modalities.

    What is it?

    Models that put different content types into one shared space, so a text query like "red running shoes" lands near photos of red running shoes.

    A bilingual dictionary, but between words and pictures.

    Where is it used?

    • Text-to-image product search, photo libraries
    • Retrieving charts, diagrams and scanned figures inside PDFs
    • Page-image retrieval for visually rich documents (e.g. ColPali-style approaches)
    • Audio search (CLAP-style models)

    When should I use it?

    When important information lives in images (diagrams, slides, scanned forms). For plain-text PDFs, a text model is simpler and cheaper.

    Example

    from sentence_transformers import SentenceTransformer
from PIL import Image
clip = SentenceTransformer("clip-ViT-B-32")
img_vec = clip.encode(Image.open("figure_3_network_diagram.png"))
txt_vec = clip.encode("diagram of the office network")
# compare with cosine similarity, same as text-only search

    Interview questions

    1. What is CLIP?A model trained on image–caption pairs so images and text share one embedding space.
    2. How would you make PDF charts searchable?Embed the chart images with a multimodal model, or caption them with a vision LLM and embed the caption.
    3. Can you mix CLIP vectors with text-only model vectors?No; they come from different models.
    4. Main trade-off of multimodal models?Broader coverage, but often weaker on pure-text retrieval than specialised text models.
    5. Give a RAG use case.A maintenance bot that retrieves the exact wiring diagram from a manual when asked about a fault.

    2. Similarity and Search

    Once content is a vector, "how relevant is this chunk?" becomes "how close are these two vectors?". This section covers the three standard ways to measure closeness and the two ways to search (exact and approximate).

    2.1

    Dot product

    Measures alignment between two vectors; commonly used for relevance scoring.

    What is it?

    Multiply matching positions and add them up: a · b = a₁b₁ + a₂b₂ + … + aₙbₙ. Bigger means more aligned. It depends on both direction and length (magnitude).

    Two people pushing a cart. If they push in the same direction the effect adds up (large positive); at right angles it's zero; in opposite directions it's negative. Stronger pushers (longer vectors) make the number bigger.

    Why is it important?

    It is the cheapest similarity to compute, and hardware is optimised for it. Many indexes use "inner product" (IP) as their native metric.

    Example

    a = np.array([1, 2, 3]); b = np.array([2, 4, 6]); c = np.array([3, 2, 1])
a @ b   # 28
a @ c   # 10

    When should I use it?

    • When vectors are normalized (then it equals cosine), or the model card says it was trained for dot product.
    • Avoid on un-normalized vectors from a cosine-trained model: long chunks may win just because their vectors are longer.

    Interview questions

    1. Formula for dot product?Sum of element-wise products.
    2. Why is dot product sensitive to magnitude?Scaling a vector by 2 doubles the score even though direction is unchanged.
    3. What is MIPS?Maximum Inner Product Search: finding vectors with the largest dot product to the query.
    4. When does dot product equal cosine similarity?When both vectors have unit length.
    5. Can dot product be negative?Yes, when vectors point in broadly opposite directions.
    2.2

    Cosine similarity

    Measures the angle between vectors; useful when direction matters more than magnitude.

    What is it?

    cos(a, b) = (a · b) / (‖a‖ × ‖b‖). Range −1 to 1. 1 = same direction, 0 = unrelated, −1 = opposite. Length is ignored.

    Two arrows on a compass. Only the angle between them matters, not how long the arrows are.

    Why is it important?

    It is the default metric for most text embedding models, and it removes the effect of text length on scores.

    Example

    def cosine(a, b): return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
cosine(a, b)   # 1.00  -> b is just a scaled copy of a
cosine(a, c)   # 0.71

    Common mistakes

    • Treating 0.8 as a universal "relevant" threshold. Score ranges differ per model.
    • Confusing cosine similarity (higher is better) with cosine distance = 1 − similarity (lower is better), which Chroma and pgvector return.

    Best practices

    • Normalize once at ingestion, then use dot product for speed.
    • Calibrate thresholds on your own evaluation set.

    Interview questions

    1. Range of cosine similarity?−1 to 1 (text embeddings usually fall between about 0 and 1).
    2. Why prefer cosine over raw dot product for text?It ignores vector length, so scores are not biased by magnitude.
    3. Cosine distance in pgvector?The <=> operator returns 1 − cosine similarity.
    4. How do you get cosine in FAISS?L2-normalize vectors, then use an inner-product index.
    5. Is a fixed threshold portable across models?No; recalibrate per model.
    2.3

    Euclidean distance

    Measures straight-line distance; smaller distance means greater similarity.

    What is it?

    ‖a − b‖ = √Σ(aᵢ − bᵢ)², also called L2 distance. 0 means identical. Unlike the two scores above, smaller is better.

    Measuring with a ruler how far apart two pins are on a map.

    Example

    np.linalg.norm(a - b)   # 3.74 -> "far", although cosine said identical direction

    For unit vectors, ‖a − b‖² = 2 − 2·cos(a, b), so L2 and cosine give the same ranking.

    MetricMeasuresBetter whenMagnitude matters?Typical use
    Dot productAlignment × lengthHigherYesNormalized vectors, models trained for IP
    Cosine similarityAngle onlyHigherNoDefault for text embeddings
    Euclidean (L2)Straight-line gapLowerYesFAISS default, clustering, images

    Interview questions

    1. Is lower or higher Euclidean distance better?Lower.
    2. Relationship between L2 and cosine for unit vectors?‖a−b‖² = 2 − 2cos, so rankings match.
    3. Default metric in Chroma?Squared L2, unless you configure cosine or inner product.
    4. Why might L2 mislead for un-normalized text vectors?Two texts with the same direction but different lengths look far apart.
    5. Which metric does IVF k-means clustering use?Typically L2 for computing centroids.

    2.4

    Normalization

    Converts vectors to unit length; after normalization, cosine similarity and dot product often produce the same ranking.

    What is it?

    Divide a vector by its own length so its length becomes exactly 1: v̂ = v / ‖v‖. Direction is kept; size is removed.

    Resizing every arrow to 1 metre so you only compare which way they point.

    Why is it important?

    After normalization, dot product equals cosine similarity, and L2 gives the same ranking. You can then use the fastest metric (inner product) and get cosine results.

    Example

    import faiss
X = embeddings.astype("float32")
faiss.normalize_L2(X)                 # in-place, every row now has length 1
index = faiss.IndexFlatIP(X.shape[1]) # inner product == cosine now
index.add(X)
q = model.encode(["refund policy"]).astype("float32"); faiss.normalize_L2(q)
scores, ids = index.search(q, 5)

    Common mistakes

    • Normalizing documents but forgetting to normalize the query.
    • Normalizing when the model was trained for un-normalized dot product (check the model card).

    Best practices

    • Use normalize_embeddings=True in Sentence-Transformers.
    • Assert np.allclose(np.linalg.norm(X, axis=1), 1) in tests.

    Interview questions

    1. What does L2 normalization do?Scales a vector to length 1 without changing its direction.
    2. Why normalize before using an IP index?So inner product equals cosine similarity.
    3. Does normalization change ranking under cosine?No; cosine already ignores length.
    4. Are OpenAI embeddings normalized?Yes, they are returned at unit length per OpenAI's docs.
    5. What bug appears if only documents are normalized?Scores and ranking become inconsistent with cosine, especially with dot product or L2.
    2.5

    Top-k retrieval

    Returns the k most similar results, such as top 5 or top 10 chunks.

    What is it?

    The search returns only the k best-scoring chunks, ranked. k is a setting you choose.

    Asking a librarian for "your 5 best books on this" rather than every book that mentions the subject.

    Why is it important?

    • k too small: the right chunk may sit at rank 6 and be missed (retrieval failure).
    • k too large: more noise, higher LLM cost and latency, and the model may get distracted.

    How does it work? Typical pattern

    %%{init: {'theme':'default'}}%%
flowchart LR
  Q["Query"] --> R["Retrieve top 30-50 (cheap)"] --> RR["Rerank (accurate)"] --> C["Keep top 3-8 for the LLM"]

    Example

    results = collection.query(query_texts=["parental leave duration"], n_results=5)
for doc, dist in zip(results["documents"][0], results["distances"][0]):
    print(round(dist, 3), doc[:80])

    Common mistakes

    • Using the same k for retrieval and for the LLM context.
    • Applying filters after top-k and ending up with fewer than k results.

    Best practices

    • Pick k using Recall@k on your evaluation set.
    • Retrieve wide, rerank, then send few.

    Interview questions

    1. How do you pick k?Measure Recall@k for several values and balance it against latency and context cost.
    2. Why retrieve 50 but send 5?Wide retrieval maximises recall; reranking then restores precision.
    3. Top-k vs similarity threshold?Top-k always returns k items; a threshold returns only items above a score and can return none.
    4. What does a larger k cost in ANN search?More candidates to explore, slightly higher latency.
    5. How does k relate to the context window?k × chunk size must fit within the LLM's budget along with the prompt and answer.
    2.6

    Exact search

    Compares the query with every stored vector; accurate but slower at scale.

    What is it?

    Brute force: compute the similarity between the query and every stored vector, then sort. It always finds the true nearest neighbours (100% recall).

    Reading every single page in the library to find the best match.

    When should I use it?

    • Small collections (up to roughly 100k vectors on CPU, more on GPU).
    • As the ground truth to measure ANN recall.
    • After a strict metadata filter leaves only a few thousand candidates.

    Cost grows linearly: 1M vectors × 768 dims ≈ 768M multiply-adds per query.

    scores = doc_matrix @ query_vec          # one score per document
top_idx = np.argsort(-scores)[:5]

    Interview questions

    1. Time complexity of exact search?O(N × d) per query.
    2. Why keep exact search around if you use ANN?To compute ground truth and measure ANN recall.
    3. When is exact search good enough in production?Small or heavily pre-filtered collections where latency is still acceptable.
    4. Which FAISS index does exact search?IndexFlatL2 or IndexFlatIP.
    5. How can exact search be sped up without approximation?Batching queries, GPU, matrix multiplication libraries, pre-filtering.
    2.7

    Approximate Nearest Neighbor (ANN)

    Trades a small amount of accuracy for much faster retrieval.

    What is it?

    Algorithms that look at only a smart subset of vectors and return almost the true nearest neighbours, often 95–99% of them, in a fraction of the time.

    Instead of reading every book, go to the right shelf section first and only browse there.

    Where is it used?

    Inside every vector database: HNSW (Chroma, pgvector, Qdrant, Weaviate, Milvus), IVF and IVF-PQ (FAISS, Milvus), ScaNN, DiskANN, Annoy.

    Interview questions

    1. Why is ANN acceptable for RAG?Missing 1–2% of neighbours rarely changes answers, and a reranker further reduces the impact.
    2. Name three ANN families.Graph-based (HNSW), clustering-based (IVF), and compression-based (PQ).
    3. How do you measure ANN quality?Recall@k versus exact search results.
    4. What knob trades speed for recall in HNSW?efSearch.
    5. Where can ANN struggle?Highly selective metadata filters and frequent deletes.

    Lab 2 · Brute-force search with NumPy

    Implement brute-force search with NumPy and compare cosine similarity with dot product.

    import numpy as np

D = model.encode(docs, normalize_embeddings=False)  # keep raw to see the difference
q = model.encode("how long do refunds take", normalize_embeddings=False)

def top_k(scores, k=5): return np.argsort(-scores)[:k]
dot = D @ q
cos = dot / (np.linalg.norm(D, axis=1) * np.linalg.norm(q))
print("dot   :", top_k(dot)); print("cosine:", top_k(cos))

print("dot after normalize:", top_k(Dn @ qn))      # identical to cosine ranking

    3. Vector Indexes

    An index is the data structure that makes search fast. Choosing one is a trade-off between recall, latency and memory.

    3.1

    Flat index

    Exact brute-force search; suitable for small datasets and as a quality baseline.

    What is it?

    A plain list of all vectors, searched exhaustively. No training, no graph. In FAISS: IndexFlatL2, IndexFlatIP.

    A shoebox of index cards you flip through one by one.

    When should I use it?

    • Prototypes and small corpora (a few thousand PDFs' worth of chunks).
    • As the recall baseline when testing HNSW or IVF.
    • Not for tens of millions of vectors with tight latency budgets.
    index = faiss.IndexFlatIP(384); index.add(X); D, I = index.search(Q, 10)

    Interview questions

    1. Does a flat index need training?No.
    2. Recall of a flat index?100% by definition.
    3. Memory of a flat index?N × d × 4 bytes, no extra structures.
    4. Why start a project with Flat?Simple, correct and gives a quality baseline.
    5. When does Flat become a problem?When latency at your corpus size exceeds your budget.
    3.2

    HNSW (Hierarchical Navigable Small World)

    Graph-based ANN index; fast and widely used, but memory-intensive.

    What is it?

    A multi-layer graph where each vector is a node linked to its nearby neighbours. Upper layers have few nodes and long links (motorways); the bottom layer has every node and short links (local streets).

    Driving across a country: take the motorway to the right region, then main roads, then local streets to the exact house.

    How does it work?

    1. Start at an entry point on the top layer.
    2. Greedily move to whichever neighbour is closer to the query.
    3. When no neighbour is closer, drop down a layer and repeat.
    4. On the bottom layer, keep a candidate list of size efSearch and return the best k.

    Common mistakes

    • Leaving efSearch below k (you cannot get more results than candidates).
    • Forgetting memory overhead of links (roughly M × 2 × 4 bytes per vector on the bottom layer).
    • Heavy delete workloads without periodic rebuilds.

    Best practices

    • Tune efSearch first; it needs no rebuild.
    • Measure recall against a Flat index.

    Interview questions

    1. Why is HNSW fast?Hierarchical greedy graph traversal visits only a small fraction of nodes, roughly logarithmic in N.
    2. What does M control?Number of neighbour links per node: recall vs memory.
    3. Which parameter can you change at query time?efSearch.
    4. HNSW's main drawback?High RAM usage, and deletes/updates are costlier than inserts.
    5. Does HNSW need training?No; it is built incrementally as vectors are inserted.

    IVF (Inverted File Index)

    Partitions vectors into clusters and searches relevant clusters; useful for large datasets.

    What is it?

    k-means groups all vectors into nlist clusters, each with a centroid. At query time, only the nprobe clusters with the nearest centroids are searched.

    A library split into subject rooms. You check only the 2–3 rooms whose topic best matches your question.

    How does it work?

    3.4

    Recall (index recall)

    Percentage of true nearest neighbors found by an ANN index.

    What is it?

    recall@k = |ANN top-k ∩ exact top-k| / k. If exact search finds 10 neighbours and HNSW returns 9 of them, recall@10 = 0.9.

    Note the two meanings of "recall" in this document: here it measures the index against exact search. In section 7, Recall@k measures retrieval against human-labelled correct chunks.

    def index_recall(ann_ids, exact_ids):
    return np.mean([len(set(a) & set(e)) / len(e) for a, e in zip(ann_ids, exact_ids)])

    Interview questions

    1. How do you compute ANN recall?Compare ANN results to exact (Flat) results for the same queries.
    2. Index recall vs retrieval Recall@k?Index recall uses exact search as truth; retrieval Recall@k uses labelled relevant chunks.
    3. What recall is "good"?Commonly 0.95+, but judge by end-to-end answer quality.
    4. How do you raise HNSW recall?Increase efSearch, or M and efConstruction with a rebuild.
    5. Can 100% index recall still give bad answers?Yes, if the embedding model or chunking is poor.
    3.5

    Latency

    Time required to return search results.

    What is it?

    Wall-clock time from sending a query to receiving results. Report p50 (typical), p95 and p99 (slow tail), not just the average. Throughput (QPS) is how many queries per second you can serve.

    import time
times = []
for q in queries:
    t = time.perf_counter(); index.search(q[None], 10); times.append(time.perf_counter() - t)
print("p50 ms", np.percentile(times, 50)*1000, "p95 ms", np.percentile(times, 95)*1000)

    Interview questions

    1. Why report p95 instead of the mean?Users feel the slow tail; averages hide it.
    2. Latency vs throughput?Time per query vs queries handled per second.
    3. Which HNSW parameter most affects query latency?efSearch.
    4. Should you include embedding time?Yes for end-to-end latency; query embedding can dominate with remote APIs.
    5. One way to cut latency without losing recall?Keep the index in RAM, batch queries, or use a GPU.

    Compresses vectors to reduce memory usage, usually with some quality loss.

    What is it?

    Storing each vector with fewer bits. Like saving a photo as a compressed JPEG instead of a raw image.

    3. How do you recover quality lost to quantization?Rescoring top candidates with original vectors.
    4. When is quantization worth it?When memory or cost limits are hit at large scale.
    5. What does IVF-PQ combine?Cluster-based search with compressed vector storage.

    4. Vector Databases

    A vector database wraps an index with everything an application needs: storage, IDs, metadata, filters, updates, deletes, isolation, and often keyword search and reranking hooks.

    4.1

    Collection / Index

    Container for vectors and associated metadata.

    What is it?

    A named container, like a table, holding records of {id, vector, text, metadata}. It is created with a fixed dimension and distance metric.

    A filing cabinet dedicated to one kind of document, with a fixed size of folder.

    Chroma, Qdrant, MilvusCollection
    PineconeIndex (with namespaces inside)

    • Different embedding models or dimensions.
    • Very different content that is never searched together.

    2. What is fixed when creating a collection?Vector dimension and distance metric (and in some DBs, index type).
    3. Collection vs namespace?Collections are separate containers; namespaces partition data within one.

    Metadata

    Additional fields such as document ID, page number, section title, source, owner, and date.

    What is it?

    Structured fields stored next to each vector. The vector says what it means; metadata says where it came from and who may see it.

    The label on a library book's spine: author, shelf, year, which branch owns it.

    Why is it important?

    • Citations: "Source: Leave_Policy.pdf, page 4".

    Upsert

    Inserts a new record or updates an existing record using the same ID.

    What is it?

    "Update or insert": if the ID exists, replace it; otherwise add it. Running the same ingestion twice gives the same result (idempotent).

    Saving a file with the same name: it overwrites rather than creating "copy (2)".

    Why is it important?

    Without upsert and stable IDs, re-running ingestion creates duplicate chunks, and the LLM sees the same passage three times.

    import hashlib
def chunk_id(doc_id, i): return f"{doc_id}#{i:04d}"
col.upsert(ids=[chunk_id("hr-leave-2024", i) for i in range(len(chunks))],
           documents=chunks, metadatas=metas)
    -- pgvector
INSERT INTO chunks (id, doc_id, content, embedding) VALUES ($1, $2, $3, $4)
ON CONFLICT (id) DO UPDATE SET content = EXCLUDED.content, embedding = EXCLUDED.embedding;

    Watch out. If a document shrinks from 30 chunks to 25, upserting 25 leaves chunks 26–30 behind as stale data. Delete by doc_id first, or delete leftover IDs.

    Interview questions

    1. What makes ingestion idempotent?Deterministic IDs plus upsert.
    2. How should chunk IDs be generated?From stable inputs such as doc_id and chunk index, or a content hash.
    3. Upsert vs add in Chroma?add fails/ignores existing IDs; upsert replaces them.
    4. Why can upsert alone leave stale data?Old chunks with IDs no longer produced are never overwritten.
    5. Does upsert re-embed text?Only if you pass new text or vectors; cache embeddings by hash to save cost.

    Delete

    Removes a vector and its metadata.

    What is it?

    Removing records by ID or by metadata filter. Needed when documents are removed, replaced, or must be erased for legal reasons (e.g. GDPR requests).

    2. What is a tombstone?A marker that hides a deleted item until the index is compacted.
    3. Why might the index stay large after deletes?Soft deletes keep space until compaction or rebuild.
    4. What risk do missing deletes create?Stale or retracted content appears in answers.
    5. How do you prove a deletion for compliance?Log the delete, query by ID to confirm absence, and handle backups too.

    Namespace / Partition

    Separates data by tenant, team, environment, or document type.

    What is it?

    A logical division inside a collection or database so searches only touch one slice. Pinecone calls it a namespace; Weaviate has multi-tenancy; Milvus has partitions; Postgres has table partitioning or a tenant_id column.

    Separate drawers in one cabinet: one per customer.

    Why is it important?

    • Isolation: customer A must never see customer B's chunks.
    • Speed: searching a small partition is faster.
    • Housekeeping: drop a whole tenant or a staging environment in one call.

    2. When use per-tenant collections?Few large tenants with strict isolation or different models.
    3. How do you separate dev and prod data?Different namespaces, collections or databases per environment.
    4. What is the risk with a shared collection?A missing tenant filter leaks data across customers.

    Hybrid search

    Combines keyword/BM25 search with vector similarity search.

    What is it?

    Run keyword search and vector search on the same query, then merge both ranked lists into one.

    Asking two experts: one who remembers exact wording, one who understands ideas. You trust results both agree on most.

    Why is it important?

    Real questions mix both needs: "What does error E-4012 mean when resetting my password?". The code needs keywords; the intent needs semantics. Hybrid search is one of the most reliable quality wins in production RAG.

    How does it work?

    Reciprocal Rank Fusion (RRF): score(d) = Σ 1 / (60 + rank_in_list). It uses ranks, not raw scores, so BM25 and cosine don't need comparable scales.

    def rrf(lists, k=60):
    scores = {}
    for ranked in lists:
        for rank, doc_id in enumerate(ranked, start=1):
            scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)
    return sorted(scores, key=scores.get, reverse=True)

    Reranking

    Reorders initial retrieval results using a more accurate but slower model.

    What is it?

    A second pass: take the top 20–50 candidates and score each one by reading the query and chunk together (a cross-encoder), then keep the best few.

    Recruiting: a keyword scan of 1,000 CVs picks 30, then a human reads those 30 carefully and picks 5 for interview.

    Bi-encoder (embedding)Cross-encoder (reranker)
    InputQuery and chunk separatelyQuery + chunk as one pair
    SpeedVery fast; chunks pre-embeddedSlow; one model call per pair
    AccuracyGoodBetter
    RoleRecall (find candidates)Precision (order them)
    from sentence_transformers import CrossEncoder
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
cands = retrieve(query, k=30)
scores = reranker.predict([(query, c.text) for c in cands])
top5 = [c for _, c in sorted(zip(scores, cands), key=lambda x: -x[0])][:5]

    Options: BAAI/bge-reranker-base, Cohere Rerank, Voyage rerank, or an LLM as a judge.

    Common mistakes

    • Reranking only 5 candidates (nothing to reorder).
    • Reranking 500 candidates and blowing the latency budget.

    Best practices

    • Rerank 20–50, keep 3–8.
    • Measure NDCG before and after; keep it only if it helps.

    Interview questions

    1. Why not use a cross-encoder for all retrieval?It would need one model call per document per query; far too slow.
    2. Which metric shows reranker value?NDCG or MRR, since reranking changes order more than membership.
    3. Typical candidate count?20–100 depending on latency budget.
    4. Can reranking fix a retrieval failure?No; it can only reorder chunks that were retrieved.
    5. What does a reranker score represent?Estimated relevance of that chunk to that query.

    Layout awareness

    Important for multi-column documents, tables, headers, footers, and forms.

    What is it?

    Understanding the visual structure of a page, so text is read in the right order and tables, headers and form fields are recognised as such.

    Text cleaning

    Remove repeated headers/footers, broken line breaks, page artifacts, and boilerplate.

    What is it?

    Post-processing extracted text so only meaningful content remains, joined into natural sentences.

    Tidying photocopies: cut off page numbers and letterheads, tape broken sentences back together.

    How does it work?

    import re, collections
def clean_pages(pages):
    # 1. lines repeated on most pages = header/footer
    first_last = collections.Counter(l.strip() for p in pages for l in (p.splitlines()[:2] + p.splitlines()[-2:]))
    furniture = {l for l, c in first_last.items() if c >= 0.6 * len(pages) and l}
    out = []
    for p in pages:
        lines = [l for l in p.splitlines() if l.strip() not in furniture]
        t = "\n".join(lines)
        t = re.sub(r"(\w)-\n(\w)", r"\1\2", t)          # infor-\nmation -> information
        t = re.sub(r"(?<![.\n:])\n(?!\n)", " ", t)     # join wrapped lines
        t = re.sub(r"^\s*Page \d+( of \d+)?\s*$", "", t, flags=re.M)
        t = re.sub(r"[ \t]+", " ", t)
        out.append(t.strip())
    return out

    Common mistakes

    • Over-cleaning: removing headings, numbers or bullet structure that chunking needs.
    • Joining table rows into one long sentence.

    Best practices

    • Keep paragraph breaks (\n\n); recursive chunking uses them.
    • Normalize Unicode (unicodedata.normalize("NFKC", t)) and ligatures like "ﬁ".

    Interview questions

    1. Why remove headers and footers?They repeat in every chunk, adding noise and false matches.
    2. How do you detect them automatically?Lines appearing at the same position on most pages.
    3. What is the danger of aggressive cleaning?Losing structure (headings, lists) and facts (numbers).
    4. Why fix hyphenated line breaks?"infor-mation" won't match "information" in keyword search.
    5. Where does cleaning sit in the pipeline?After parsing, before chunking.

    6. Chunking Logic

    Chunking decides what a "search result" is. It is one of the highest-impact and most tunable parts of any RAG system.

    6.1

    Chunk

    A smaller piece of a document that is embedded and retrieved independently.

    What is it?

    A passage cut from a document (a few paragraphs, a section, a table) that gets its own vector and can be returned on its own.

    Index cards made from a textbook. You hand the student the 3 cards that answer the question, not the whole book.

    Why is it important?

    • A 200-page PDF embedded as one vector becomes a blurry average of every topic in it.
    • LLM context is limited and costs money; you want to send only relevant passages.
    • Small units make citations precise ("page 14, section 3.2").

    Where does it fit?

    %%{init: {'theme':'default'}}%%

  P["Parsed and cleaned text"] --> C["Chunker"] --> C1["Chunk 1 + metadata"] & C2["Chunk 2 + metadata"] & C3["Chunk N + metadata"]
  C1 & C2 & C3 --> E["Embed each"] --> DB["Vector DB"]

    Interview questions

    1. Why not embed whole documents?One vector can't represent many topics well, and whole documents don't fit LLM context.
    2. What makes a good chunk?Self-contained, about one idea, within token limits, with metadata for citation.
    3. Is a chunk always text?Mostly, but it can be a table, an image caption, or a code block.
    4. What happens if chunks cut mid-sentence?Meaning is split; overlap or sentence-aware splitting helps.
    5. Which chunk settings should you tune first?Size and overlap, using an evaluation set.
    6.2

    Chunk size (too small vs too large)

    Number of tokens or characters per chunk. Too small: loses surrounding context. Too large: dilutes meaning and may exceed embedding model limits.

    What is it?

    The target length of each chunk, measured in tokens (preferred) or characters.

    Photo zoom. Too close and you can't tell what you're looking at; too far and the detail you need is a tiny speck.

    Too small (e.g. 50–100 tokens)Balanced (≈ 300–600)Too large (e.g. 2000+)
    MeaningFragments; pronouns lose their subject ("It must be approved…")One coherent ideaMany topics averaged together
    Retrieval precisionHigh per chunk but often missing contextGoodLow; vectors become vague
    Number of vectorsVery many (cost, memory)ModerateFew
    LLM context useNeed many chunksEfficientWasteful; irrelevant text included
    Token-limit riskNoneLowMay exceed embedding limits and be truncated

    Example

    Too small: "It must be approved by a manager." (What must?) · Too large: an entire 10-page HR policy where leave, expenses and IT rules are mixed into one vector.

    Interview questions

    1. Tokens or characters for chunk size?Tokens, because model limits and costs are in tokens.
    2. Symptom of chunks too small?Retrieved snippets lack the subject or conditions needed to answer.
    3. Symptom of chunks too large?Relevant chunks rank low because their vectors mix many topics.
    4. Does the best size depend on the question type?Yes: factoid lookups prefer smaller chunks; "explain" questions prefer larger.
    5. How do you find the right size?Run experiments over several sizes and compare Recall@k.
    6.3

    Overlap

    Repeated text between adjacent chunks to preserve context across boundaries.

    What is it?

    The last N tokens of one chunk are repeated at the start of the next, so a sentence or idea cut at a boundary still appears whole in at least one chunk.

    Text:    [==========================================================]
Chunk 1: [==============]
Chunk 2:            [==============]          overlap = shared part
Chunk 3:                       [==============]
                    ^^^^       ^^^^
                    repeated tokens keep boundary sentences intact

    Rule of thumb from the source: 10–20%. For 500-token chunks: 50–100 tokens overlap. Stride = size − overlap.

    Common mistakes

    • Overlap ≥ 50%: storage doubles and the same passage appears twice in results.
    • Zero overlap with fixed-size splitting, which cuts sentences in half.

    Best practices

    • De-duplicate overlapping neighbours before sending to the LLM.
    • With structure-aware chunking, less overlap is needed.

    Interview questions

    1. Why add overlap?To keep information that spans a boundary retrievable in one chunk.
    2. Cost of overlap?More chunks, more storage and embedding cost, possible duplicate results.
    3. Typical overlap?10–20% of chunk size.
    4. What is stride?Chunk size minus overlap: how far the window moves each step.
    5. When can overlap be zero?When chunks follow natural boundaries like sections or full paragraphs.
    6.4

    Fixed-size chunking

    Splits by token or character count; simple and effective baseline.

    What is it?

    Cut every N tokens, with an optional overlap, ignoring sentence and section boundaries.

    Slicing a loaf into equal slices regardless of where the raisins are.

    import tiktoken
enc = tiktoken.get_encoding("cl100k_base")
def fixed_chunks(text, size=500, overlap=75):
    ids = enc.encode(text)
    step = size - overlap
    return [enc.decode(ids[i:i+size]) for i in range(0, len(ids), step)]

    Use when: you need a quick baseline, or text has no structure (transcripts, logs). Avoid when: documents have clear sections and tables.

    Interview questions

    1. Main advantage?Simple, fast, predictable sizes.
    2. Main drawback?Cuts through sentences, tables and sections.
    3. Why is it still a good baseline?It often performs surprisingly well and is easy to compare against.
    4. How do you reduce boundary damage?Add 10–20% overlap.
    5. Characters vs tokens here?Tokens give consistent embedding-limit safety.
    6.5

    Splits using separators such as paragraphs, sentences, then words.

    What is it?

    Try to split on the biggest natural boundary first (blank lines between paragraphs). If a piece is still too big, split it on the next boundary (newline, then sentence end, then space).

    Cutting a document with scissors: first between chapters, then between paragraphs only where needed, and between words only as a last resort.

    Structure-aware chunking

    Uses headings, sections, tables, and document hierarchy.

    What is it?

    Split along the document's own structure: each section or subsection becomes a chunk (split further only if too long), and the heading path travels with it.

    Cutting a manual along its table of contents instead of with a ruler.

    2. Why add heading paths to chunk text?It gives the chunk its missing context and improves retrieval.
    3. What if a section is huge?Split it recursively, keeping the heading path on each piece.
    4. What if a section is tiny?Merge it with siblings under the same parent.
    5. Best document types for this method?Manuals, policies, contracts, documentation sites.
    6.7

    Semantic chunking

    Groups sentences by meaning; test it rather than assuming it is always better.

    What is it?

    Embed each sentence, then start a new chunk wherever the meaning shifts sharply (similarity between consecutive sentences drops below a threshold).

    Splitting a conversation transcript whenever the topic changes.

    How does it work?

    1. Split text into sentences.
    2. Embed each sentence (or small window).
    3. Compute similarity between neighbours.
    4. Cut where similarity falls below a percentile (e.g. the lowest 5%).

                          breakpoint_threshold_type="percentile")
chunks = chunker.split_text(clean_text)

    3. Where are parents stored?In a document store or key-value store; they need no vectors.
    4. Risk?Large parents eat context; several children from one parent must be de-duplicated.
    5. What is auto-merging retrieval?If enough children of one parent are retrieved, return the parent instead.

    Table handling

    Tables need special handling; avoid splitting them mid-row.

    Why is it important?

    A row like | Grade 5 | 25 days | means nothing without its header | Grade | Annual leave |. Splitting mid-table, or flattening it into a sentence soup, destroys the answer.

    How to handle tables

    1. Extract tables as structured objects (Docling, pdfplumber, Unstructured) and convert to Markdown or HTML.
    2. Keep small tables as one chunk.
    3. Split large tables by groups of rows, repeating the header row in every piece.
    4. Add a one-line description ("Table 4: Annual leave days by grade, 2024") or an LLM summary, embed that, and return the full table.
    5. For numeric questions over big tables, consider loading them into SQL instead of embedding.
    def split_table(header, rows, rows_per_chunk=20, caption=""):
    for i in range(0, len(rows), rows_per_chunk):
        yield "\n".join([caption, header, "|---|---|"] + rows[i:i+rows_per_chunk])

    Interview questions

    1. Why repeat headers when splitting tables?Each piece must be understandable on its own.
    2. Best text format for tables in RAG?Markdown or HTML, which LLMs read well.
    3. How do you make tables findable by meaning?Embed a caption or summary that describes the table.
    4. When use SQL instead?Large numeric tables needing aggregation or exact lookup.
    5. What breaks if a parser flattens tables?Row/column relationships are lost, causing wrong answers.

    7. RAG and Retrieval Evaluation

    RAG connects retrieval to an LLM. Evaluation tells you whether a change actually helped, and whether a bad answer came from retrieval or from generation.

    7.1

    RAG (Retrieval-Augmented Generation)

    Retrieves relevant chunks and provides them to an LLM as context.

    What is it?

    Instead of relying on what the LLM memorised during training, you first retrieve passages from your own documents and augment the prompt with them, then the LLM generates an answer grounded in those passages.

    An open-book exam. The student (LLM) is smart, but answers from the pages you hand them, and cites them.

    Why is it important?

    • LLMs don't know your private or recent documents.
    • Grounding reduces hallucination and enables citations.
    • Updating knowledge = updating the index, not retraining a model.

    Where is it used?

    HR/IT policy chatbots, customer-support assistants, legal and contract Q&A, engineering documentation search, "chat with your PDFs" tools.

    When should I use it?

    • Use RAG when answers live in documents that change or are private.
    • Not needed if the whole corpus fits comfortably in the context window and cost is fine (just include it).
    • Fine-tuning teaches style/format, not fresh facts; it complements rather than replaces RAG.

    Common mistakes

    • No instruction to refuse when context is missing, so the LLM guesses.

    • Show citations in the UI.
    • Log question, retrieved IDs, scores and answer for every request.

    2. How does RAG reduce hallucination?The model answers from supplied evidence and can be told to refuse without it.
    3. Two halves of a RAG system?Retrieval (find chunks) and generation (write the answer).
    4. How do you add citations?Include source metadata with each chunk and instruct the model to cite.
    5. When is RAG unnecessary?When all needed content fits in the prompt cheaply, or the task needs no external facts.

    Context window

    Maximum text an LLM can process in one request.

    What is it?

    The total token budget for one LLM call: system prompt + retrieved chunks + chat history + question + the answer it writes.

    The size of the desk. Everything the student uses for this question must fit on it at once.

    Budget item (example)Tokens
    System instructions300
    Chat history (condensed)500
    6 chunks × 500 tokens3,000
    Question50
    Reserved for answer800
    Total4,650

    Large windows (100k+ tokens) don't remove the need for retrieval: cost and latency scale with tokens, and models can miss facts buried in the middle of long prompts ("lost in the middle").

    Interview questions

    1. What counts toward the context window?All input tokens plus the generated output.
    2. Why not stuff 100 chunks into a long-context model?Higher cost and latency, and attention to relevant facts drops.
    3. What is "lost in the middle"?Models use information at the start and end of a prompt better than in the middle.
    4. How do you fit long chat histories?Summarise or condense history into a standalone question.
    5. Where to place the most relevant chunk?Near the start (or end) of the context, not buried in the middle.

    7.5

    Recall@k

    Whether the correct chunk appears in the top-k retrieved results.

    What is it?

    For each question: 1 if a correct chunk is in the top k, else 0. Average across questions. Recall@5 = 0.8 means 80% of questions had the answer somewhere in the top 5.

    def recall_at_k(retrieve, eval_set, k=5):
    hits = 0
    for ex in eval_set:
        chunks = retrieve(ex["question"], k)
        hits += any(ex["expected_passage"][:60].lower() in c.text.lower() for c in chunks)
    return hits / len(eval_set)

    Recall@k is the most important retrieval metric for RAG: if the chunk isn't retrieved, the LLM can't use it.

    Interview questions

    1. Define Recall@k.Fraction of questions where a relevant chunk appears in the top k results.
    2. Does Recall@k care about order within k?No; that's what NDCG/MRR measure.
    3. Recall@5 = 0.6. What next?Inspect misses; try hybrid search, chunking changes, or a better embedding model.
    4. Why is Recall@10 ≥ Recall@5 always?A larger k includes all smaller-k results.
    5. How do you define a "hit" with changing chunk boundaries?Match by passage text or page, not chunk ID.
    7.6

    NDCG (Normalized Discounted Cumulative Gain)

    Measures ranking quality; gives higher credit when correct results appear earlier.

    What is it?

    A score from 0 to 1 that rewards relevant results more when they appear near the top.

    • DCG@k = Σ rel_i / log₂(i + 1) for positions i = 1…k.
    • NDCG@k = DCG@k / IDCG@k, where IDCG is the DCG of the perfect ordering.

    Worked example (one relevant chunk)

    Interview questions

    1. Why NDCG and not just Recall@k?It also rewards putting the right chunk first.
    2. What does the log discount do?Reduces credit for results lower in the list.
    3. NDCG vs MRR?MRR looks only at the first relevant result; NDCG handles multiple and graded relevance.
    4. Which component is NDCG best for evaluating?Rerankers.
    5. NDCG if the only relevant chunk is at rank 2?About 0.63.

    Minimal working code (about 40 lines)

    import pymupdf, chromadb
from langchain_text_splitters import RecursiveCharacterTextSplitter
from sentence_transformers import SentenceTransformer, CrossEncoder

embedder = SentenceTransformer("BAAI/bge-small-en-v1.5")
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(chunk_size=450, chunk_overlap=60)
col = chromadb.PersistentClient("./kb").get_or_create_collection("docs", metadata={"hnsw:space": "cosine"})

def ingest(path, doc_id):
    ids, texts, metas = [], [], []
    for pno, page in enumerate(pymupdf.open(path), start=1):            # 1-2 upload + parse
        text = " ".join(page.get_text().split())                         # 3 (very light) cleaning
        for i, chunk in enumerate(splitter.split_text(text)):            # 4 chunking
            ids.append(f"{doc_id}#p{pno}-{i}"); texts.append(chunk)
            metas.append({"doc_id": doc_id, "source": path, "page": pno})
    vecs = embedder.encode(texts, normalize_embeddings=True).tolist()    # 5 embedding
    col.delete(where={"doc_id": doc_id})                                 # remove stale chunks
    col.upsert(ids=ids, embeddings=vecs, documents=texts, metadatas=metas)   # 6 storage

def answer(question, llm):
    q = embedder.encode(question, normalize_embeddings=True).tolist()    # 7-8 query embedding
    r = col.query(query_embeddings=[q], n_results=20)                    # 9 retrieval
    cands = list(zip(r["documents"][0], r["metadatas"][0]))
    scores = reranker.predict([(question, d) for d, _ in cands])         # 10 reranking
    top = [c for _, c in sorted(zip(scores, cands), key=lambda x: -x[0])][:5]
    ctx = "\n\n".join(f"[{m['source']} p.{m['page']}] {d}" for d, m in top)
    prompt = ("Answer only from the context and cite [source p.page]. "
              "If the answer is not there, say you don't know.\n\n"
              f"Context:\n{ctx}\n\nQuestion: {question}")
    return llm(prompt)                                                   # 11 generation

    30-Day Practical Learning Roadmap
