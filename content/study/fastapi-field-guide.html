Chapter 1 · API foundations

What is an API?

APInoun · Application Programming Interface

A defined way for one program to ask another program to do something or give it data. A web API does this over HTTP: a client sends a request to a URL, the server does the work, and sends back a response, usually JSON, with a status code that says whether it worked.

Every app you use talks to APIs. When a hospital app shows a patient's record, the phone does not open the database. It calls something like GET /patient/P001 on a server, and the server answers with that patient's data. The API is the contract between the two sides: which URLs exist, what to send, what comes back, and what each error means.

Example

Client, server, database

Any client (a browser, a mobile app, Postman, another server, an automated test) speaks the same HTTP to the same API. The client never touches the data store directly.

Easy definition

An API is a menu of operations a server offers. A REST API exposes that menu as URLs plus HTTP methods, takes and returns JSON, and reports the outcome with a status code.

Which code does a request get?

FastAPI checks a request in a fixed order. The first check that fails decides the status code, which is why a request can be wrong in several ways but only reports one family of error.

400 vs 422: the question every tester asks

422 Unprocessable Content

FastAPI's automatic answer when the request does not match the declared schema: a mandatory field is missing, a type is wrong ("age": "abc"), a format is wrong (bad email, id not matching ^P\d{3,6}$), a value is out of range, or the JSON cannot be parsed. You write no code for these.

400 Bad Request

What you raise with HTTPException(400, …) for rules the schema cannot express: sort_by must be one of height/weight/bmi, a discharge date must be after the admission date, and so on.

Both mean "the client sent something wrong". Many teams and many test plans expect 400 for every bad input. If your organisation wants that, convert FastAPI's validation errors to 400 with one exception handler. This is optional and not part of the canonical app, so the rest of this guide expects 422 for schema errors.

optional: return 400 with a clean error list instead of 422
from fastapi import Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    errors = [
        {
            "field": ".".join(str(p) for p in err["loc"][1:]) or err["loc"][0],
            "type": err["type"],
            "message": err["msg"],
        }
        for err in exc.errors()
    ]
    return JSONResponse(status_code=400, content={"detail": "Validation failed", "errors": errors})

With the handler registered, a body with four problems returns one 400 listing all of them:

400 {"detail": "Validation failed", "errors": [ {"field": "id", "type": "string_pattern_mismatch", "message": "String should match pattern '^P\\d{3,6}$'"}, {"field": "name", "type": "string_too_short", "message": "String should have at least 2 characters"}, {"field": "age", "type": "int_parsing", "message": "Input should be a valid integer, unable to parse string as an integer"}, {"field": "weight", "type": "missing", "message": "Field required"}]}
Register handlers before the first request

Exception handlers are wired into the app when it handles its first request. Add them at import time, next to app = FastAPI(), not later at runtime.

Rule for test design

Write the expected status for every test case down before running it, based on this chapter. A test that "passes" because it got any 4xx hides bugs: a missing-field case that returns 404 or 500 is a failure even though it was rejected.

Chapter 4 · API foundations

REST API design

REST (Representational State Transfer) is a set of conventions, not a library. The core idea: model your domain as resources (patients, visits, prescriptions), give each one a URL, and use HTTP methods as the verbs. If every API follows the same conventions, a developer or tester can guess most endpoints without reading the docs.

Resources and CRUD

OperationIdiomatic RESTPatient API (tutorial style)Success code
ListGET /patientsGET /view200
Read oneGET /patients/{id}GET /patient/{patient_id}200
CreatePOST /patientsPOST /create201
ReplacePUT /patients/{id}(none)200 / 204
Partial updatePATCH /patients/{id}PUT /edit/{patient_id} (behaves like PATCH)200
DeleteDELETE /patients/{id}DELETE /delete/{patient_id}204 / 200

The Patient API keeps the endpoint names from your FastAPI notes so the code stays familiar. Notice two things a reviewer would flag: verbs in paths (/create, /edit) duplicate what the HTTP method already says, and PUT /edit accepts partial bodies, which is PATCH semantics. For a new API, prefer the idiomatic column.

Design rules that save pain later

  • Nouns, plural, lowercase, hyphens: /patients, /lab-results. Nest only one level: /patients/P001/visits.
  • Methods carry the verb. Use a POST sub-resource only for real actions: POST /patients/P001/discharge.
  • Return the right status code (Chapter 3), and a Location header with 201.
  • Filter, sort and page with query params: ?city=Pune&sort=-bmi&limit=20&offset=40. Always cap limit.
  • One error format everywhere, for example {"detail": "...", "errors": [...]}, so clients and test tools parse errors one way (Chapter 9).
  • Version when you break compatibility: /v1/patients in the path is simplest to see in logs and Postman.
  • Make retries safe: GET/PUT/DELETE are idempotent; for POSTs that create payments or orders, accept an Idempotency-Key header.
  • Document with OpenAPI. FastAPI generates it for you at /openapi.json, and Postman can import it directly (Chapter 19).

Chapter 5 · FastAPI core

What is FastAPI? Install and first app

FastAPInoun · Python web framework

A modern Python framework for building APIs from type hints. You write ordinary functions with typed arguments; FastAPI reads the types and automatically parses the request, validates it, converts it, returns clear errors, serialises the response, and generates interactive documentation.

FastAPI is a thin, well-designed layer over two proven libraries: Starlette (the web toolkit: routing, middleware, requests, WebSockets) and Pydantic (data validation). It runs on an ASGI server such as Uvicorn, which handles the network and the async event loop.

Why teams pick it

  • Validation for free. Declare age: int = Field(gt=0, lt=120) and bad input is rejected with a precise 422 before your function runs.
  • Docs for free. Swagger UI at /docs lets you try every endpoint; /openapi.json imports straight into Postman.
  • Editor support. Because everything is typed, autocomplete and type checkers catch mistakes as you type.
  • Async when you need it. async def endpoints handle many slow I/O calls (LLMs, other APIs) concurrently.
  • Dependency injection for auth, database sessions and settings, which also makes testing easy.

Path and query parameters

Path parameters

Put a name in braces in the path, and add a function argument with the same name. The type hint drives conversion and validation; Path() adds metadata and constraints that appear in /docs.

path parameter (from the Patient API)
from typing import Annotated
from fastapi import FastAPI, HTTPException, Path, status

@app.get("/patient/{patient_id}")
def view_patient(
    patient_id: Annotated[str, Path(description="ID of the patient in the DB", examples=["P001"])],
):
    data = load_data()
    if patient_id not in data:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Patient not found")
    return data[patient_id]

With a numeric type, conversion is automatic and invalid values are rejected. For @app.get("/item/{item_id}") with item_id: int:

Route order matters

Routes are matched top to bottom. Declare fixed paths (/patient/count) before parameterised ones (/patient/{patient_id}), or "count" will be captured as a patient id.

Query parameters

Any function argument that is not in the path and has a simple type (str, int, float, bool, list of those) is a query parameter. No default means required; a default means optional. This is the same mandatory/optional rule you will see for body fields in Chapter 7.

query parameters (from the Patient API)
from fastapi import Query

@app.get("/sort")
def sort_patients(
    sort_by: Annotated[str, Query(description="Sort on height, weight or bmi")],   # required
    order: Annotated[str, Query(description="asc or desc")] = "asc",               # optional
):
    valid = ["height", "weight", "bmi"]
    if sort_by not in valid:
        raise HTTPException(status.HTTP_400_BAD_REQUEST, f"Invalid field, select from {valid}")
    if order not in ("asc", "desc"):
        raise HTTPException(status.HTTP_400_BAD_REQUEST, "Invalid order, select between asc and desc")
    data = load_data()
    return sorted(data.values(), key=lambda p: p.get(sort_by, 0), reverse=(order == "desc"))

Chapter 7 · FastAPI core

Pydantic models: mandatory vs optional fields

A request body is described by a class that inherits from BaseModel. Each attribute is a field with a type, and optionally a default and constraints. Whether a field is mandatory (the client must send it) or non-mandatory (the client may leave it out) is decided by one thing: does it have a default value?

The one rule

No default → mandatory. Has a default (even None) → optional. The type decides what values are allowed; Optional[X] only means "null is an allowed value". It does not make the field optional by itself.

Strict mode and extra fields

Two rows above surprise most testers: "age": "30" is accepted (Pydantic's default lax mode converts numeric strings), and unknown fields are silently ignored. Tighten both when your contract requires it:

strict types and forbidden extras
from pydantic import BaseModel, ConfigDict

class StrictPatient(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")
    name: str
    age: int
{"name": "A", "age": "30"} → 422 int_type "Input should be a valid integer" {"name": "A", "age": 30, "blood": "O+"} → 422 extra_forbidden "Extra inputs are not permitted" loc ["body","blood"]

You can also make a single field strict with Annotated[int, Field(strict=True)]. Whatever you choose, the test suite must assert it, so a library upgrade cannot quietly change the contract.

Request body and validation errors

Declare a Pydantic model as a function argument and FastAPI treats it as the JSON body. By the time your function runs, the body has been parsed, validated, converted and turned into a typed object. If anything fails, your function never runs and the client gets a 422.

body parameter

Chapter 9 · FastAPI core

Responses, status codes and errors

Set the success code

The default success code is 200. Set another one on the decorator: @app.post("/create", status_code=201). Use the named constants in fastapi.status (status.HTTP_201_CREATED) to avoid typos.

Shape the output with response_model

A response model filters and documents what leaves the server. Even if the stored record contains an email, the response below only includes id, name and city. This is how you avoid leaking internal or sensitive fields.

response_model
class PatientOut(BaseModel):
    id: str
    name: str
    city: str

@app.get("/p/{pid}", response_model=PatientOut)
def get_patient(pid: str):
    return DB[pid]          # {"id": "P001", "name": "Ananya", "city": "Guwahati", "email": "a@x.com"}
# response body: {"id": "P001", "name": "Ananya", "city": "Guwahati"}

Useful options: response_model_exclude_none=True drops null fields; response_model_exclude={"email"} drops named fields. You can also use a return type annotation (def get_patient(...) -> PatientOut:) for the same effect.

Errors with HTTPException

HTTPException, with optional headers
from fastapi import HTTPException, status

raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Patient not found")
raise HTTPException(status_code=429, detail="Slow down", headers={"Retry-After": "30"})

Raising stops the function immediately and returns {"detail": ...} with that status. detail can be any JSON-serialisable value: a string or a dict like {"code": "DUPLICATE_ID", "message": "..."}.

Custom exceptions and handlers

For larger apps, raise domain exceptions in your business code and translate them to HTTP in one place. The business code then has no HTTP knowledge, and every error has the same shape.

from fastapi import Request

@app.exception_handler(PatientNotFound)

One error format for the whole API

The canonical app returns two error shapes: {"detail": "text"} from HTTPException, and {"detail": [ … ]} from validation. That is FastAPI's default and is fine. Do not put stack traces, SQL or file paths in error responses. Log them on the server with a request id, and return the id to the client.

Chapter 11 · Production FastAPI

Dependency injection

A dependency is a function (or class) that FastAPI calls for you before your endpoint and whose result it passes in. You declare it with Depends(). Dependencies can read query parameters, headers and the body just like endpoints, can depend on other dependencies, and can raise HTTPException to stop the request. They are how FastAPI apps share auth, database sessions, settings and pagination without copy-paste.

three kinds of dependency
from typing import Annotated, Optional
from fastapi import Depends, FastAPI, Header, HTTPException, Query, status

app = FastAPI()

# 1) A function dependency: shared pagination parameters
def pagination(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> dict:
    return {"limit": limit, "offset": offset}

Page = Annotated[dict, Depends(pagination)]

# 2) A dependency that only guards (returns nothing)
API_KEY = "secret-key"
def require_api_key(x_api_key: Annotated[Optional[str], Header()] = None) -> None:
    if x_api_key is None:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Missing X-API-Key header")
    if x_api_key != API_KEY:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "Invalid API key")

# 3) A yield dependency: setup before, cleanup after the request
class FakeSession:
    def __init__(self): self.closed = False
    def close(self): self.closed = True

def get_session():
    session = FakeSession()
    try:
        yield session
    finally:
        session.close()

SessionDep = Annotated[FakeSession, Depends(get_session)]

@app.get("/patients")
def list_patients(page: Page, session: SessionDep):
    return {"page": page, "session_open": not session.closed}

@app.delete("/patients/{pid}", dependencies=[Depends(require_api_key)])
def delete_patient(pid: str):
    return {"deleted": pid}
PatternUse it for
Returns a value (pagination)Shared parameters, the current user, settings
Guard in dependencies=[…] (require_api_key)Checks that only allow or deny: auth, feature flags, rate limits
yield dependency (get_session)Resources that need cleanup: DB sessions, files, locks
Router-level: APIRouter(dependencies=[Depends(...)])Protect a whole group of endpoints at once

The testing superpower

Any dependency can be replaced in tests: app.dependency_overrides[get_session] = lambda: fake_session. Tests then run without a real database or real credentials. Always clear the overrides afterwards (app.dependency_overrides.clear()).

The Annotated[dict, Depends(pagination)] alias (Page above) is the recommended style: declare it once, reuse it in every endpoint, and the editor still knows the type.

from typing import Annotated, Literal, Optional

from fastapi import Depends, FastAPI, HTTPException, Query, status
from sqlmodel import Field, Session, SQLModel, create_engine, select

DATABASE_URL = "sqlite:///./patients.db"          # Postgres: "postgresql+psycopg://user:pass@db:5432/app"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})  # arg only for SQLite


class PatientBase(SQLModel):
    name: str = Field(min_length=2, max_length=50)
    city: str = Field(min_length=2, max_length=50, index=True)
    age: int = Field(gt=0, lt=120)
    gender: Literal["male", "female", "other"]   # validated on input (stored as text)
    height: float = Field(gt=0, lt=3)
    weight: float = Field(gt=0, lt=500)
    email: Optional[str] = None


class PatientDB(PatientBase, table=True):          # the table
    __tablename__ = "patients"
    id: str = Field(primary_key=True)
    gender: str                                    # Literal has no SQL type: store as text


class PatientCreate(PatientBase):                  # what clients send
    # Note: SQLModel's regex= is not enforced with Pydantic v2; pass the pattern like this
    id: str = Field(schema_extra={"pattern": r"^P\d{3,6}$"})


def get_session():
    with Session(engine) as session:
        yield session

SessionDep = Annotated[Session, Depends(get_session)]


@asynccontextmanager
async def lifespan(app: FastAPI):
    SQLModel.metadata.create_all(engine)           # dev only: use Alembic migrations in real projects
    yield

app = FastAPI(lifespan=lifespan)


@app.post("/patients", status_code=status.HTTP_201_CREATED, response_model=PatientDB)
def create_patient(data: PatientCreate, session: SessionDep):
    if session.get(PatientDB, data.id):
        raise HTTPException(status.HTTP_409_CONFLICT, "Patient already exists")
    patient = PatientDB.model_validate(data)
    session.add(patient)
    session.commit()
    session.refresh(patient)
    return patient


@app.get("/patients", response_model=list[PatientDB])
def list_patients(
    session: SessionDep,
    city: Optional[str] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
):
    stmt = select(PatientDB)
    if city:
        stmt = stmt.where(PatientDB.city == city)
    return session.exec(stmt.offset(offset).limit(limit)).all()


@app.get("/patients/{patient_id}", response_model=PatientDB)
def get_patient(patient_id: str, session: SessionDep):
    patient = session.get(PatientDB, patient_id)
    if not patient:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Patient not found")
    return patient


@app.delete("/patients/{patient_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_patient(patient_id: str, session: SessionDep):
    patient = session.get(PatientDB, patient_id)
    if not patient:

Key ideas

  • One session per request, provided by a yield dependency, closed automatically after the response. Never share a session between requests.
  • Separate models: what clients send (PatientCreate), what is stored (PatientDB), and, when they differ, what is returned (PatientPublic). This keeps internal columns (password hashes, audit fields) out of responses.
  • Duplicates and missing rows become HTTP codes in your code (409, 404), exactly as with the JSON file. Also catch the database's IntegrityError for unique constraints that race.
  • Migrations: create_all() only creates missing tables; it never alters existing ones. Use Alembic (alembic init, alembic revision --autogenerate -m "add phone", alembic upgrade head) to version schema changes.
  • Async option: SQLAlchemy supports AsyncSession with async drivers (asyncpg, psycopg async). Use it with async def endpoints; use the sync session with plain def endpoints (Chapter 15).
Two SQLModel gotchas (checked with sqlmodel 0.0.50)

1) Literal types have no SQL column type, so the table model overrides gender as str while the input model keeps the Literal check. 2) SQLModel's Field(regex=...) is not enforced under Pydantic v2; pass the pattern with schema_extra={"pattern": ...} as shown, or validate in a plain Pydantic model. A test caught this: "id": "Q2" was accepted until the fix.

Chapter 13 · Production FastAPI

Authentication and authorisation

Authentication · 401

Who are you? Missing, malformed, wrong or expired credentials. Response should include WWW-Authenticate.

Authorisation · 403

Are you allowed? The caller is known, but their role or key does not permit this action.

Option 1: API key header (the Patient API)

Simple and good for server-to-server calls and internal tools. The canonical app protects DELETE /delete/{id} with the require_api_key dependency: no header → 401, wrong key → 403, right key → the delete runs. Load the key from the environment (API_KEY), rotate it, and give each client its own key in real systems so you can revoke one without breaking others.

Option 2: OAuth2 password flow with JWT

For user logins. The user posts a username and password once, receives a signed JSON Web Token, and sends it on every request in Authorization: Bearer <token>. The server verifies the signature and expiry without a database lookup.

Security essentials

Load SECRET_KEY from the environment, never from code. Hash passwords with Argon2 or bcrypt, never store or log plain text. Keep access tokens short-lived (15–60 minutes) and use refresh tokens for long sessions. Never put sensitive data in a JWT payload: it is signed, not encrypted, and anyone can decode it. Middleware, CORS and logging

Middleware wraps every request and response. It runs before routing and after your endpoint, so it is the place for cross-cutting concerns: logging, timing, request ids, CORS, compression, security headers. Middleware added last runs first (it is the outermost layer).

    allow_origins=["http://localhost:3000", "https://app.example.com"],   # never "*" with credentials

@app.middleware("http")
async def log_requests(request: Request, call_next):
    request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))
    start = time.perf_counter()
    try:
        response = await call_next(request)
    except Exception:
        log.exception("id=%s %s %s -> 500 unhandled", request_id, request.method, request.url.path)
        raise
    elapsed_ms = (time.perf_counter() - start) * 1000
    response.headers["X-Request-ID"] = request_id
    response.headers["X-Process-Time-ms"] = f"{elapsed_ms:.1f}"
    log.info("id=%s %s %s -> %s in %.1f ms", request_id, request.method, request.url.path,
             response.status_code, elapsed_ms)
    return response

CORS in plain words

Browsers block JavaScript on https://app.example.com from reading responses from https://api.example.com unless the API says that origin is allowed. Before "non-simple" requests (JSON POST, custom headers like X-API-Key), the browser sends an OPTIONS preflight; CORSMiddleware answers it. CORS only affects browsers: Postman, curl and server-to-server calls ignore it, which is why "it works in Postman but not in the browser" is almost always CORS.

CORS rules

List exact origins. allow_origins=["*"] is acceptable only for truly public, credential-free APIs, and cannot be combined with allow_credentials=True. CORS is not security against non-browser clients: you still need authentication.

Logging that helps you debug

  • Log one line per request: method, path, status, duration, request id. Return the id in a response header so a user or tester can quote it.
  • Use JSON logs in production (python-json-logger, structlog) so a log platform can filter by status or path.
  • Never log passwords, tokens, API keys or full medical records. Log ids instead.
  • Other useful built-ins: GZipMiddleware, TrustedHostMiddleware, HTTPSRedirectMiddleware.

import asyncio
import time
from contextlib import asynccontextmanager

import httpx
from fastapi import BackgroundTasks, FastAPI, WebSocket, WebSocketDisconnect


@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.http = httpx.AsyncClient(timeout=10)   # create shared resources once
    yield
    await app.state.http.aclose()                    # clean up on shutdown

app = FastAPI(lifespan=lifespan)


@app.get("/sync-report")
def sync_report():                 # plain def: FastAPI runs it in a thread pool
    time.sleep(0.1)                # blocking call is OK here
    return {"kind": "sync"}


@app.get("/async-report")
async def async_report():          # async def: runs on the event loop
    await asyncio.sleep(0.1)       # must only await non-blocking calls
    return {"kind": "async"}


def write_audit_log(patient_id: str, action: str) -> None:
    with open("audit.log", "a", encoding="utf-8") as f:
        f.write(f"{patient_id} {action}\n")


@app.post("/patients/{patient_id}/notify", status_code=202)
def notify(patient_id: str, background: BackgroundTasks):
    background.add_task(write_audit_log, patient_id, "notified")   # runs after the response is sent
    return {"message": "Notification queued"}


@app.websocket("/ws/vitals")
async def vitals(ws: WebSocket):
    await ws.accept()
    try:
        while True:
            reading = await ws.receive_json()               # e.g. {"heart_rate": 82}
            alert = reading.get("heart_rate", 0) > 120
            await ws.send_json({"received": reading, "alert": alert})
    except WebSocketDisconnect:
        pass

  • lifespan creates shared resources (HTTP clients, DB pools, ML models) once at startup and cleans them up at shutdown. It replaces the old @app.on_event("startup").
  • BackgroundTasks run after the response is sent, in the same process. Good for small jobs (audit logs, emails). If the process restarts, queued tasks are lost: use a real queue for anything that must not be dropped.
  • WebSockets keep a two-way connection open: live vitals, chat, streaming LLM tokens. Test them with TestClient.websocket_connect() or Postman's WebSocket request type.

1. Path parameters

Write the URL as {{baseUrl}}/patient/:patientId. Postman detects :patientId and adds a Path Variables table under the Params tab, where you type P001 (or {{existingId}}). This keeps the URL readable and lets data files fill the value.

Which field failed? Reading a 422

A correct status is not enough for a negative test. If you send a bad age and get 422 because of a bad email, the test proved nothing. FastAPI lists each problem in detail[], and the last element of loc names the field (structure explained in Chapter 7):

Pre-request script: build the body from the data row
// Build the body for this data row. "AUTO" ids become unique so reruns do not hit 409.
const row = pm.iterationData.toObject();
if (row.raw_body !== undefined) {
    pm.variables.set("requestBody", row.raw_body);          // deliberately broken JSON
} else {
    const body = row.body || {};
    if (body.id === "AUTO") body.id = "P" + Math.floor(100000 + Math.random() * 899999);
    pm.variables.set("requestBody", JSON.stringify(body));
}
Post-response script: one generic test for every row
const row = pm.iterationData.toObject();
const expected = Number(row.expected_status);
pm.test(`[${row.case_id}] ${row.description} -> expect ${expected}`, () => {
    pm.response.to.have.status(expected);

Chapter 24 · Build a test tool

Designing an automated API testing tool

Postman's data-driven runs (Chapter 22) work, but someone still has to write every row. For an endpoint with ten fields, the complete set of missing, wrong-type, wrong-format, boundary, null and empty cases is around seventy rows, and it must be rewritten whenever a field changes. In this part we design and build a small Python tool, apitest, that:

  • reads a field spec (which fields exist, which are mandatory, their types, formats and limits) and generates every scenario automatically;
  • also accepts a hand-written dataset (CSV, JSON or Excel) from QA for extra cases on any endpoint;
  • sends each request, captures the HTTP status and its meaning, and compares it with the expected status;
  • for every failure records why it failed (wrong status, wrong field blamed, schema mismatch, timeout, connection error);
  • stores a log of each run (JSONL) plus a history database (SQLite) to compare runs over time;
  • writes an HTML report and a CSV summary, and returns a non-zero exit code so CI fails the build.

How the failure reason is decided

Design decisions worth copying

  • Omit vs null are different inputs. The generator uses a special OMIT marker to drop a key, and a real None to send null. Mixing them up is the most common bug in hand-written suites.
  • Unique ids per run. Every success case gets a fresh id (P483920…) so reruns never produce false 409s. The duplicate test deliberately reuses the previous case's body.
  • Setup steps for dependent cases. DELETE tests first create their own record (setup_create), so they never delete seed data and never depend on order.
  • Expectations live in data. Changing the API contract (say, returning 400 instead of 422 for validation errors) means changing validation_status in the spec, not code.
  • Logs are append-only and flushed per case. If the run crashes halfway, everything up to that point is still on disk.
  • Secrets on the command line or in env vars, never in specs or datasets ({api_key} placeholder).

2. Loading the spec

Dataclasses mirror the JSON. Loading fails early with a clear message if a field has an unknown type or no valid sample, because a broken spec would otherwise produce dozens of confusing failures.

apitest/spec.py
"""Load and validate a field spec (JSON) that describes one endpoint's request body."""
import json
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any


@dataclass
class FieldSpec:
    name: str
    type: str                      # string | integer | number | enum | email | array | boolean
    mandatory: bool
    valid: Any                     # a value the API must accept
    nullable: bool | None = None   # None -> defaults to "not mandatory"
    pattern: str | None = None
    enum: list | None = None
    min_length: int | None = None
    max_length: int | None = None
    gt: float | None = None
    lt: float | None = None
    invalid: dict = field(default_factory=dict)   # optional overrides: {"wrong_type": ..., "wrong_format": ...}

    @property
    def accepts_null(self) -> bool:
        return (not self.mandatory) if self.nullable is None else self.nullable


@dataclass
class EndpointSpec:
    name: str
    method: str
    path: str
    success_status: int
    validation_status: int
    fields: list[FieldSpec]
    id_field: str | None = None
    duplicate_status: int | None = None
    success_required_keys: list[str] = field(default_factory=list)
    max_ms: int | None = None
    extra_cases: list[dict] = field(default_factory=list)

    @property
    def mandatory(self) -> list[FieldSpec]:
        return [f for f in self.fields if f.mandatory]

    @property
    def optional(self) -> list[FieldSpec]:
        return [f for f in self.fields if not f.mandatory]


VALID_TYPES = {"string", "integer", "number", "enum", "email", "array", "boolean"}


def load_spec(path: str | Path) -> EndpointSpec:
    raw = json.loads(Path(path).read_text(encoding="utf-8"))
    fields = []
    for f in raw["fields"]:
        if f["type"] not in VALID_TYPES:
            raise ValueError(f"Field {f['name']!r}: unknown type {f['type']!r}")
        if "valid" not in f:
            raise ValueError(f"Field {f['name']!r}: a 'valid' sample value is required")
        fields.append(FieldSpec(**f))
    ep = raw["endpoint"]
    return EndpointSpec(
        name=raw["name"],
        method=ep["method"].upper(),
        path=ep["path"],
        success_status=raw.get("success_status", 200),
        validation_status=raw.get("validation_status", 422),
        fields=fields,
        id_field=raw.get("id_field"),
        duplicate_status=raw.get("duplicate_status"),
        success_required_keys=raw.get("success_required_keys", []),
        max_ms=raw.get("max_ms"),
        extra_cases=raw.get("extra_cases", []),
    )

3. The scenario generator (the heart of the tool)

body() builds a valid body and applies overrides; OMIT removes a key. generate() walks the categories from Chapter 24; _boundary_cases() produces the at-limit and just-inside values for numbers and text.

apitest/scenarios.py
"""Generate every test scenario automatically from an EndpointSpec."""
import random
from dataclasses import dataclass, field
from typing import Any

from .spec import EndpointSpec, FieldSpec

OMIT = object()   # sentinel: "leave this key out of the body" (different from sending null)


@dataclass
class TestCase:
    case_id: str
    category: str
    description: str
    method: str
    path: str
    expected_status: int
    body: Any = None                        # dict, list, or None
    raw_body: str | None = None             # for malformed JSON
    params: dict = field(default_factory=dict)
    headers: dict = field(default_factory=dict)
    expected_error_field: str | None = None  # for 422s: which field must be blamed
    setup_create: bool = False               # create a fresh record first, then use {created_id}
    repeat_of: str | None = None             # duplicate test: send the same body as this case


class UniqueIds:
    """Hands out run-unique ids such as P483920 so reruns never collide (409)."""

    def __init__(self, prefix: str = "P", digits: int = 6):
        self.prefix, self.digits = prefix, digits
        self.next = random.randint(10 ** (digits - 1), 9 * 10 ** (digits - 1))

    def new(self) -> str:
        self.next += 1
        return f"{self.prefix}{self.next}"


# ---------- default bad values per type ----------
def wrong_type_value(f: FieldSpec) -> Any:
    if "wrong_type" in f.invalid:
        return f.invalid["wrong_type"]
    return {
        "string": 12345,          # number where text expected
        "email": 12345,
        "enum": 12345,
        "integer": "abc",         # text where a number expected ("30" would be coerced!)
        "number": "abc",
        "array": "not-a-list",
        "boolean": "maybe",
    }[f.type]


def wrong_format_value(f: FieldSpec) -> Any | None:
    if "wrong_format" in f.invalid:
        return f.invalid["wrong_format"]
    if f.type == "email":
        return "not-an-email"
    if f.type == "enum":
        return "unknown-option"
    if f.pattern:
        return "@@bad-format@@"
    return None


class ScenarioGenerator:
    def __init__(self, spec: EndpointSpec, ids: UniqueIds | None = None):
        self.spec = spec
        self.ids = ids or UniqueIds()
        self.counter = 0

    # ----- helpers -----
    def _valid_value(self, f: FieldSpec) -> Any:
        if f.name == self.spec.id_field:
            return self.ids.new()
        return f.valid

    def body(self, overrides: dict | None = None, only: list[str] | None = None) -> dict:
        """A valid body; `overrides` replaces values (OMIT removes the key); `only` keeps a subset."""
        overrides = overrides or {}
        out = {}
        for f in self.spec.fields:
            if only is not None and f.name not in only:
                continue
            value = overrides.get(f.name, self._valid_value(f))
            if value is not OMIT:
                out[f.name] = value
        for k, v in overrides.items():          # extra (unknown) fields
            if k not in out and v is not OMIT and k not in {f.name for f in self.spec.fields}:
                out[k] = v
        return out

    def _case(self, category, description, expected, **kw) -> TestCase:
        self.counter += 1
        return TestCase(
            case_id=f"TC{self.counter:03d}",
            category=category,
            description=description,
            method=self.spec.method,
            path=self.spec.path,
            expected_status=expected,
            **kw,
        )

    # ----- the scenario catalogue -----
    def generate(self) -> list[TestCase]:
        s, ok, bad = self.spec, self.spec.success_status, self.spec.validation_status
        cases: list[TestCase] = []
        mand = [f.name for f in s.mandatory]

        cases.append(self._case("valid_all", "All mandatory and optional fields valid", ok, body=self.body()))
        cases.append(self._case("valid_mandatory_only", "Only mandatory fields", ok, body=self.body(only=mand)))

        for f in s.mandatory:
            cases.append(self._case("missing_mandatory", f"Mandatory '{f.name}' omitted", bad,
                                    body=self.body({f.name: OMIT}), expected_error_field=f.name))
        for f in s.optional:
            cases.append(self._case("missing_optional", f"Optional '{f.name}' omitted", ok,
                                    body=self.body({f.name: OMIT})))

        half = mand[: max(1, len(mand) // 2)]
        missing = [m for m in mand if m not in half]
        cases.append(self._case("partial", f"Partial body: only {', '.join(half)}", bad,
                                body=self.body(only=half),
                                expected_error_field=missing[0] if missing else None))

        for f in s.fields:
            cases.append(self._case("wrong_type", f"'{f.name}' has the wrong type", bad,
                                    body=self.body({f.name: wrong_type_value(f)}), expected_error_field=f.name))
            fmt = wrong_format_value(f)
            if fmt is not None:
                cases.append(self._case("wrong_format", f"'{f.name}' has the wrong format ({fmt!r})", bad,
                                        body=self.body({f.name: fmt}), expected_error_field=f.name))
            cases += self._boundary_cases(f)
            cases.append(self._case("null_value", f"'{f.name}' sent as null",
                                    ok if f.accepts_null else bad,
                                    body=self.body({f.name: None}),
                                    expected_error_field=None if f.accepts_null else f.name))
            if f.type in ("string", "email"):
                rejects_empty = bool(f.min_length or f.pattern or f.type == "email")
                cases.append(self._case("empty_string", f"'{f.name}' sent as empty string",
                                        bad if rejects_empty else ok,
                                        body=self.body({f.name: ""}),
                                        expected_error_field=f.name if rejects_empty else None))

        cases.append(self._case("extra_field", "Unknown extra field is ignored", ok,
                                body=self.body({"unexpected_field": "hello"})))
        cases.append(self._case("empty_body", "Empty JSON object", bad, body={}))
        cases.append(self._case("malformed_json", "Body is not valid JSON", bad, raw_body='{"id": "P1",'))

        if s.duplicate_status and s.id_field:
            first = self._case("duplicate", "Create a record (first of a pair)", ok, body=self.body())
            second = self._case("duplicate", "Same id again must conflict", s.duplicate_status,
                                body=None, repeat_of=first.case_id)
            cases += [first, second]

        for extra in s.extra_cases:
            cases.append(self._case(
                extra["category"], extra["description"], extra["expected_status"],
                body=extra.get("body"), params=extra.get("params", {}), headers=extra.get("headers", {}),
                setup_create=extra.get("setup_create", False),
            ))
            cases[-1].method = extra.get("method", s.method).upper()
            cases[-1].path = extra.get("path", s.path)
        return cases

    def _boundary_cases(self, f: FieldSpec) -> list[TestCase]:
        ok, bad, out = self.spec.success_status, self.spec.validation_status, []
        if f.type in ("integer", "number"):
            step = 1 if f.type == "integer" else 0.01
            if f.gt is not None:
                out.append(self._case("boundary", f"'{f.name}' = {f.gt} (must be > {f.gt})", bad,
                                      body=self.body({f.name: f.gt}), expected_error_field=f.name))
                out.append(self._case("boundary", f"'{f.name}' just above lower limit", ok,
                                      body=self.body({f.name: round(f.gt + step, 2)})))
            if f.lt is not None:
                out.append(self._case("boundary", f"'{f.name}' = {f.lt} (must be < {f.lt})", bad,
                                      body=self.body({f.name: f.lt}), expected_error_field=f.name))
                out.append(self._case("boundary", f"'{f.name}' just below upper limit", ok,
                                      body=self.body({f.name: round(f.lt - step, 2)})))
        if f.type == "string" and f.name != self.spec.id_field:
            if f.min_length:
                out.append(self._case("boundary", f"'{f.name}' shorter than {f.min_length} chars", bad,
                                      body=self.body({f.name: "x" * (f.min_length - 1)}), expected_error_field=f.name))
            if f.max_length:
                out.append(self._case("boundary", f"'{f.name}' longer than {f.max_length} chars", bad,
                                      body=self.body({f.name: "x" * (f.max_length + 1)}), expected_error_field=f.name))
                out.append(self._case("boundary", f"'{f.name}' exactly {f.max_length} chars", ok,
                                      body=self.body({f.name: "x" * f.max_length})))
        return out

5. Assertions and failure reasons

The function returns a list of reasons; an empty list means pass. This is the decision tree of Figure 24 in code.

apitest/assertions.py
"""Decide pass/fail for one response and explain WHY it failed."""
from .scenarios import TestCase
from .status_codes import meaning


def error_fields(payload) -> list[str]:
    """Field names blamed by a FastAPI/Pydantic 422: detail[].loc[-1]."""
    if not isinstance(payload, dict) or not isinstance(payload.get("detail"), list):
        return []
    out = []
    for err in payload["detail"]:
        loc = err.get("loc") or []
        if loc:
            out.append(str(loc[-1]))
    return out


def check(case: TestCase, status: int | None, payload, duration_ms: float,
          required_keys: list[str], max_ms: int | None, error: str | None) -> list[str]:
    """Return a list of failure reasons. Empty list = PASS."""
    reasons: list[str] = []
    if status is None:
        return [f"No response: {error}"]

    if status != case.expected_status:
        reasons.append(
            f"Status mismatch: expected {case.expected_status} ({meaning(case.expected_status).split(':')[0]}), "
            f"got {status} ({meaning(status).split(':')[0]})"
        )
        if status == 422:
            blamed = error_fields(payload)
            if blamed:
                reasons.append(f"API rejected field(s): {', '.join(blamed)}")
        return reasons

    if status == 422 and case.expected_error_field:
        blamed = error_fields(payload)
        if case.expected_error_field not in blamed:
            reasons.append(
                f"Right status, wrong reason: expected error on '{case.expected_error_field}', "
                f"API blamed {blamed or 'nothing'}"
            )

    if 200 <= status < 300 and required_keys and isinstance(payload, dict):
        missing = [k for k in required_keys if k not in payload]
        if missing:
            reasons.append(f"Schema mismatch: response missing keys {missing}")

    if max_ms is not None and duration_ms > max_ms:
        reasons.append(f"Too slow: {duration_ms:.0f} ms > {max_ms} ms budget")
    return reasons

6. The runner

One httpx.Client is reused for connection pooling. Timeouts and connection errors are caught and turned into records instead of crashing the run. The response-shape check (success_required_keys) applies only to the spec's own endpoint: the first real run of this tool flagged GET /patient/P001 and the DELETE case as "schema mismatch" because the check was applied to every 2xx, which is exactly the kind of tool bug a first run should surface.

apitest/runner.py
"""Send each TestCase over HTTP and produce a result record."""
import json
import time
from datetime import datetime, timezone

import httpx

from .assertions import check
from .scenarios import ScenarioGenerator, TestCase
from .spec import EndpointSpec
from .status_codes import meaning


class Runner:
    def __init__(self, base_url: str, spec: EndpointSpec | None, api_key: str | None = None,
                 timeout: float = 10.0):
        self.client = httpx.Client(base_url=base_url, timeout=timeout)
        self.spec = spec
        self.api_key = api_key
        self.sent_bodies: dict[str, dict] = {}        # case_id -> body (for duplicate tests)
        self.gen = ScenarioGenerator(spec) if spec else None

    def close(self):
        self.client.close()

    def _create_fresh_record(self) -> str:
        """Setup step for cases like DELETE: create a valid record and return its id."""
        body = self.gen.body()
        r = self.client.post(self.spec.path, json=body)
        r.raise_for_status()
        return body[self.spec.id_field]

    def _headers(self, case: TestCase) -> dict:
        headers = dict(case.headers)
        for k, v in headers.items():                  # "{api_key}" placeholder from the CLI
            if v == "{api_key}":
                headers[k] = self.api_key or ""
        return headers

    def run_case(self, run_id: str, case: TestCase) -> dict:
        path, body = case.path, case.body
        if case.repeat_of:
            body = self.sent_bodies.get(case.repeat_of)
        error, status, payload, text = None, None, None, ""
        try:
            if case.setup_create:
                path = path.replace("{created_id}", self._create_fresh_record())
            kwargs = {"params": case.params, "headers": self._headers(case)}
            if case.raw_body is not None:
                kwargs["content"] = case.raw_body.encode()
                kwargs["headers"] = {**kwargs["headers"], "Content-Type": "application/json"}
            elif body is not None:
                kwargs["json"] = body
            start = time.perf_counter()
            resp = self.client.request(case.method, path, **kwargs)
            duration_ms = (time.perf_counter() - start) * 1000
            status, text = resp.status_code, resp.text
            try:
                payload = resp.json()
            except ValueError:
                payload = None
        except httpx.TimeoutException as exc:
            duration_ms, error = 0.0, f"timeout ({exc.__class__.__name__})"
        except httpx.HTTPStatusError as exc:          # only raised by the setup step
            duration_ms, error = 0.0, f"setup failed: {exc.response.status_code} {exc.response.text[:120]}"
        except httpx.HTTPError as exc:
            duration_ms, error = 0.0, f"connection error ({exc.__class__.__name__}: {exc})"

        if body is not None:
            self.sent_bodies[case.case_id] = body
        # The response-shape check belongs to the spec's own endpoint only (not to extra/dataset URLs)
        on_spec_endpoint = bool(self.spec) and (case.method, case.path) == (self.spec.method, self.spec.path)
        spec_keys = self.spec.success_required_keys if on_spec_endpoint else []
        max_ms = self.spec.max_ms if self.spec else None
        reasons = check(case, status, payload, duration_ms, spec_keys, max_ms, error)
        return {
            "run_id": run_id,
            "timestamp": datetime.now(timezone.utc).isoformat(timespec="seconds"),
            "case_id": case.case_id,
            "category": case.category,
            "description": case.description,
            "method": case.method,
            "url": str(self.client.base_url).rstrip("/") + path,
            "request_body": body if case.raw_body is None else case.raw_body,
            "expected_status": case.expected_status,
            "actual_status": status,
            "status_meaning": meaning(status),
            "result": "PASS" if not reasons else "FAIL",
            "failure_reason": "; ".join(reasons) or None,
            "response_excerpt": (text or "")[:300],
            "duration_ms": round(duration_ms, 1),
        }


def new_run_id() -> str:
    return datetime.now().strftime("run_%Y%m%d_%H%M%S")


def to_json(record: dict) -> str:
    return json.dumps(record, ensure_ascii=False)

7. Logging: JSONL per run, SQLite across runs

JSON Lines (one JSON object per line) is easy to append, grep, and load into pandas. SQLite keeps a summary per run and every result row, so trends need one SQL query.

apitest/store.py
"""Persist results: one JSONL file per run + a SQLite history across runs."""
import json
import sqlite3
from pathlib import Path

SCHEMA = """
CREATE TABLE IF NOT EXISTS runs (
    run_id TEXT PRIMARY KEY, started_at TEXT, base_url TEXT, spec TEXT,
    total INTEGER, passed INTEGER, failed INTEGER
);
CREATE TABLE IF NOT EXISTS results (
    run_id TEXT, case_id TEXT, category TEXT, description TEXT, method TEXT, url TEXT,
    expected_status INTEGER, actual_status INTEGER, result TEXT, failure_reason TEXT,
    duration_ms REAL, timestamp TEXT,
    PRIMARY KEY (run_id, case_id)
);
"""


class ResultStore:
    def __init__(self, out_dir: str | Path, run_id: str):
        self.dir = Path(out_dir)
        self.dir.mkdir(parents=True, exist_ok=True)
        self.run_id = run_id
        self.jsonl_path = self.dir / f"{run_id}.jsonl"
        self._jsonl = self.jsonl_path.open("w", encoding="utf-8")
        self.db = sqlite3.connect(self.dir / "history.db")
        self.db.executescript(SCHEMA)

    def write(self, rec: dict) -> None:
        self._jsonl.write(json.dumps(rec, ensure_ascii=False) + "\n")
        self._jsonl.flush()                      # survive a crash mid-run
        self.db.execute(
            "INSERT OR REPLACE INTO results VALUES (?,?,?,?,?,?,?,?,?,?,?,?)",
            (rec["run_id"], rec["case_id"], rec["category"], rec["description"], rec["method"],
             rec["url"], rec["expected_status"], rec["actual_status"], rec["result"],
             rec["failure_reason"], rec["duration_ms"], rec["timestamp"]),
        )

    def finish(self, started_at: str, base_url: str, spec: str, records: list[dict]) -> None:
        passed = sum(r["result"] == "PASS" for r in records)
        self.db.execute(
            "INSERT OR REPLACE INTO runs VALUES (?,?,?,?,?,?,?)",
            (self.run_id, started_at, base_url, spec, len(records), passed, len(records) - passed),
        )
        self.db.commit()
        self.db.close()
        self._jsonl.close()


def history(out_dir: str | Path, limit: int = 10) -> list[tuple]:
    db = sqlite3.connect(Path(out_dir) / "history.db")
    rows = db.execute(
        "SELECT run_id, started_at, total, passed, failed, "
        "ROUND(100.0 * passed / total, 1) FROM runs ORDER BY started_at DESC LIMIT ?", (limit,)
    ).fetchall()
    db.close()
    return rows

def parse_args(argv=None):
    p = argparse.ArgumentParser(prog="apitest", description="Data-driven API test runner")
    p.add_argument("--base-url", default="http://127.0.0.1:8000")
    p.add_argument("--spec", help="Field spec JSON: cases are generated from it")
    p.add_argument("--cases", help="Extra hand-written cases: .csv, .json or .xlsx")
    p.add_argument("--category", action="append",
                   help="Only run these categories (repeatable), e.g. --category missing_mandatory")
    p.add_argument("--api-key", help="Value substituted for {api_key} in case headers")
    p.add_argument("--out", default="runs", help="Folder for logs, reports and history.db")
    p.add_argument("--list", action="store_true", help="Print the generated cases and exit")
    p.add_argument("--history", type=int, metavar="N", help="Show the last N runs and exit")

def main(argv=None) -> int:
    args = parse_args(argv)
    if args.history:
        print(f"{'run_id':<22} {'started_at':<20} total  pass  fail  pass%")
        for run_id, started, total, passed, failed, pct in history(args.out, args.history):
            print(f"{run_id:<22} {started:<20} {total:>5} {passed:>5} {failed:>5} {pct:>6}")
        return 0

    spec = load_spec(args.spec) if args.spec else None
    cases = ScenarioGenerator(spec).generate() if spec else []
    if args.cases:
        cases += load_cases(args.cases)
    if args.category:
        cases = [c for c in cases if c.category in args.category]
    if not cases:
        print("No cases to run (give --spec and/or --cases).")
        return 2

    if args.list:
        for c in cases:
            print(f"{c.case_id}  {c.category:<20} expect {c.expected_status}  {c.description}")
        print(f"{len(cases)} cases")
        return 0

    run_id = new_run_id()
    started = datetime.now().isoformat(timespec="seconds")
    store = ResultStore(args.out, run_id)
    runner = Runner(args.base_url, spec, api_key=args.api_key)
    records = []
    print(f"Run {run_id}: {len(cases)} cases against {args.base_url}")
    try:
        for case in cases:
            rec = runner.run_case(run_id, case)
            records.append(rec)
            store.write(rec)
            mark = "PASS" if rec["result"] == "PASS" else "FAIL"
            line = (f"  {mark}  {rec['case_id']}  {rec['category']:<20} "
                    f"exp {rec['expected_status']} got {rec['actual_status']}  {rec['description']}")
            print(line if mark == "PASS" else f"{line}\n        reason: {rec['failure_reason']}")
    finally:
        runner.close()
        store.finish(started, args.base_url, args.spec or args.cases, records)

    out = Path(args.out)
    write_csv(records, out / f"{run_id}.csv")
    write_html(records, out / f"{run_id}.html", run_id, args.base_url)

    passed = sum(r["result"] == "PASS" for r in records)
    by_cat = Counter((r["category"], r["result"]) for r in records)
    print(f"\n{passed}/{len(records)} passed, {len(records) - passed} failed")
    for cat in dict.fromkeys(r["category"] for r in records):
        print(f"  {cat:<22} pass {by_cat[(cat, 'PASS')]:>3}  fail {by_cat[(cat, 'FAIL')]:>3}")
    print(f"Log:    {store.jsonl_path}\nReport: {out / (run_id + '.html')}\nCSV:    {out / (run_id + '.csv')}")
    return 0 if passed == len(records) else 1          # non-zero exit fails the CI job


if __name__ == "__main__":
    sys.exit(main())

4. From failure to fix

The reason tells you the API accepted "age": "30", and the response excerpt shows it stored 30 as a number. That is Pydantic's default lax mode: a numeric string is coerced to an integer. A failing test always means one of two things, and you must decide which:

The test is wrong

Coercion is acceptable for your clients. Change the row's expected_status to 201.

The API is wrong

Your contract says numbers must be JSON numbers. Make the field strict, e.g. age: Annotated[StrictInt, Field(gt=0, lt=120)] or model_config = ConfigDict(strict=True), and the test passes with 422.

When the server is not reachable at all, the reason says so instead of a confusing status mismatch:

runs/history.db: useful queries
-- Cases that failed in more than one run (regressions or flaky tests)
SELECT case_id, description, COUNT(*) AS failures
FROM results WHERE result = 'FAIL'
GROUP BY case_id HAVING COUNT(*) > 1 ORDER BY failures DESC;

-- Pass rate per category across all runs
SELECT category, ROUND(100.0 * SUM(result = 'PASS') / COUNT(*), 1) AS pass_pct
FROM results GROUP BY category ORDER BY pass_pct;

-- Cases whose status changed between the last two runs
WITH last2 AS (SELECT run_id FROM runs ORDER BY started_at DESC LIMIT 2)
SELECT a.case_id, a.actual_status AS before, b.actual_status AS after
FROM results a JOIN results b ON a.case_id = b.case_id
WHERE a.run_id = (SELECT run_id FROM last2 ORDER BY run_id LIMIT 1)
  AND b.run_id = (SELECT run_id FROM last2 ORDER BY run_id DESC LIMIT 1)
  AND a.actual_status IS NOT b.actual_status;

-- Slowest cases in the latest run
SELECT case_id, description, duration_ms FROM results
WHERE run_id = (SELECT run_id FROM runs ORDER BY started_at DESC LIMIT 1)
ORDER BY duration_ms DESC LIMIT 10;

8. Extending the tool

  • More endpoints: one spec per endpoint (update_patient.json with every field optional, success 200); loop over a specs/ folder.
  • Bearer tokens: add a login step that calls /auth/token once and injects Authorization: Bearer … into every case.
  • Speed: run independent cases concurrently with httpx.AsyncClient and asyncio.gather (keep duplicate pairs and setup-dependent cases sequential).
  • Generate specs from OpenAPI: FastAPI's /openapi.json already contains types, required lists, patterns and limits; a small converter can write the spec for you. Tools like Schemathesis take this idea further with property-based testing straight from the OpenAPI schema; they are worth running alongside your scenario suite.

Glossary

AssertionA check that must be true for a test to pass (e.g. status is 201).
Boundary valueAn input exactly at, or just inside/outside, an allowed limit.
CollectionA saved, ordered group of Postman requests, exportable as JSON.
Collection RunnerPostman's GUI for running a collection or folder, optionally once per data-file row.
Data-driven testingOne test definition executed for many input rows from a data file.
Desktop AgentA small local helper that lets the Postman web app send requests from your machine (needed for localhost).
EnvironmentA named set of Postman variables for one server (Local, Staging…).
Exit codeThe number a program returns to the shell; 0 means success, anything else fails a CI step.
Field specapitest's JSON description of an endpoint's fields, from which scenarios are generated.
Flaky testA test that passes and fails without code changes, usually because of shared data, timing or order.
Iteration dataThe current row of a data file in Postman/Newman (pm.iterationData).
JSONLJSON Lines: one JSON object per line; easy to append and stream.
JUnit XMLA standard test-report format understood by almost every CI system.
Lax vs strict modePydantic either coerces compatible inputs ("30" → 30) or rejects anything not of the exact type.
Mandatory / optional fieldA field the request must contain (no default) / may leave out (has a default).
Negative testA test that sends invalid input and expects a specific error.
NewmanOpen-source command-line runner for Postman collections (Node.js).
NullableA field that may be sent with the value null; not the same as optional.
OpenAPIA machine-readable API description; FastAPI serves it at /openapi.json.
Post-response / pre-request scriptPostman JavaScript that runs after / before a request (post-response was formerly the Tests tab).
Postman CLIPostman's official signed command-line tool for running collections and reporting to Postman.
ReporterA Newman plugin that writes results in a format (cli, junit, htmlextra…).
Request chainingUsing a value from one response (e.g. an id) in later requests.
ScenarioOne specific input situation with one expected outcome.
Smoke testA quick check that the main endpoints respond at all.
