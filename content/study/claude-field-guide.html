Study notes · Claude apps, Cowork, Claude Code & API · October 2026

Claude Field Guide

Most people use Claude like a search box: ask one question, read the answer, start over. This guide shows the rest of it. It covers every major feature, when each one is worth using, and how to put them together so Claude does more of the work.

How to read this

Part I explains what Claude is and how to choose a plan and model. Part II goes through the app's features one at a time. Part III is about writing good prompts. Part IV is for people who build things with Claude Code or the API. Part V brings it all together into everyday workflows. Chapters marked with an orange dot in the contents have Example boxes.

The examples follow one running task: the weekly Plant TAT report. Each Monday an analyst turns a spreadsheet of truck turnaround times (TAT) into a summary for plant managers. The numbers are made up.

Features change fast

This guide was checked against Anthropic's help center, pricing page and docs on 11 October 2026. Menu names, plan rules and limits change often. Before you rely on a detail, check the source links in Chapter 28.

Chapter 1 · Foundations

What Claude is

ClaudeAI model family + apps · by Anthropic

A family of AI models made by Anthropic, and the apps you use them through. Claude can read and write text, look at images and documents, write and run code, search the web, use your other apps through connectors, and carry out multi-step tasks on its own.

"Claude" means two things. The model is the AI itself, such as Opus 5.5 or Sonnet 5.5. The surfaces are the places you use it: the chat app, Cowork, Claude Code, browser and Office add-ins, Slack, and the API for developers. Every surface uses the same models, but each one gives Claude different tools.

Example

Where Claude lives

The same models power every surface. What changes is what Claude can touch: your messages only, your files, your browser, your apps, or your codebase.

SurfaceWhat it isUse it when
Chat appsclaude.ai in a browser, the desktop app (Mac, Windows) and the mobile appThinking, writing, analysing, asking questions
CoworkAn agent that works through multi-step tasks on its own, using folders and apps you give it"Go and do this" jobs that take many steps
Claude CodeAn agent that reads, writes and runs code in a projectBuilding or changing software, scripts, websites

Key idea

Claude is no longer just a chatbot. It can keep context in a Project, produce real files and apps, work in your tools, and finish tasks while you do something else. Getting good at Claude mostly means knowing which of these to use for the job in front of you.

Chapter 2 · Foundations

Beyond chat: the mindset shift

Plain chat treats each conversation as a blank start. You paste context, get a reply, copy it somewhere, and next week you do it all again. Using Claude well means moving up a ladder, from one-off answers to setups that remember your context and do the work for you.

Example

The weekly TAT report, done three ways

ApproachWhat you do each MondayTime
Plain chatOpen a new chat, explain the plant again, paste the data, ask for a summary, fix the format, copy it into an email.~40 min
Project + skillOpen the "TAT report" Project. It already knows the plant, the targets and your report format. Upload the file and say "this week's report". You get a finished Word file and a chart.~10 min
Scheduled agentA Cowork scheduled task reads the new file from the shared folder each Monday at 8:00, writes the report, and drafts the email. You check it and press send.~3 min

Four habits that make the shift

  1. Give context once, not every time. Put standing information in a Project, your instructions or a skill (Chapters 5, 9, 11).
  2. Ask for the finished thing. Ask for the spreadsheet, the deck or the working page, not a description of it (Chapters 6–7).
  3. Let Claude reach the source. Connect Drive, email or the web instead of copying and pasting (Chapters 8, 10).
  4. Hand off, then review. For multi-step jobs, describe the outcome, let an agent do the steps, and check the result (Chapters 12, 19).

How the limits work

  • A rolling 5-hour window. Your allowance refills over time rather than once a day. Paid plans also have a weekly cap.
  • One shared pool. Chat, Cowork, Claude Code, the desktop and mobile apps all count against the same allowance.
  • No fixed message count. What counts is the work done. Long chats, big files, bigger models, higher effort and agent tasks all use more.
Which plan?

Try Free to learn the basics. Pro is the usual choice for daily work, because it adds Opus, Research, Cowork and Claude Code. Choose Max only if you keep hitting Pro's limits. Teams that share Projects and need admin control should use Team.

Chapter 4 · Foundations

Models, effort and thinking

Use the model menu next to the Send button to choose a model, an effort level and thinking. Bigger models are smarter but slower, and they use up your allowance faster.

ModelCharacterGood for
Fable 5.1The top tier, the most capableThe hardest reasoning, research and long agent tasks (Max, Team Premium, Enterprise)
Opus 5.5Very capable, deep reasoningComplex analysis, important writing, serious coding
Sonnet 5.5Fast and strong, the everyday defaultMost work: drafting, summarising, analysis, everyday coding
Haiku 5.5The fastest and lightestQuick questions, rewording, sorting, simple extraction

Older models are listed under "More models".

Effort and thinking

Effort sets how hard Claude works on each reply. The levels are Low, Medium, High, Extra high and Max. Higher effort means more careful reasoning, slower answers and more usage. On the current models, thinking (Claude reasoning step by step before it answers) is always on. Effort is the control you actually adjust.

Example

Matching model and effort to the task

TaskModelEffort
"Make this email to the transporter more polite"Haiku or SonnetLow
"Summarise this week's TAT data and flag anomalies"SonnetDefault
"Why did TAT rise 18% at Gate 2? Test three explanations against the data"OpusHigh
"Review this vendor contract for risk clauses before we sign"Opus or FableExtra high / Max
Rule of thumb

Start with Sonnet at the default effort. Move up only when the answer is shallow or wrong. Move down for simple, repetitive jobs. That is the easiest way to make your allowance last.

Chapter 5 · The app toolkit

Projects

Projectworkspace · all plans (Free: up to 5)

A workspace with its own chats, a set of knowledge files Claude can read in every chat, and project instructions that apply to every chat inside it.

Projects fix the biggest waste in plain chat: explaining the same background again and again. Upload the reference material once and write the standing rules once. Every new chat in the Project starts with them. On paid plans, when the knowledge files get large, Claude switches to searching them, so a Project can hold far more than one chat can.

How to set one up

  1. Sidebar → Projects → New project. Give it a clear name and a one-line description.
  2. Add knowledge: reference documents, templates, glossaries, past examples of good work.
  3. Write instructions: who the audience is, the format, the tone, and the rules.
  4. Start a new chat in the Project for each task. Keep one topic per chat.
Example

The "Plant TAT report" Project

Knowledge files: plant-layout.pdf, tat-targets.xlsx (target TAT by gate and vehicle type), report-sample-good.docx (a past report the managers liked), glossary.md.

Project instructions
You help the logistics analyst at a manufacturing plant write the weekly
truck turnaround-time (TAT) report.

Audience: plant managers. They read on their phones and have 2 minutes.

Always:
- Start with a 3-line summary: overall TAT vs target, the biggest change,
  and one recommended action.
- Compare every gate against tat-targets.xlsx.
- Call any gate more than 15% over target "red", 5-15% "amber".
- Use the structure of report-sample-good.docx.
- If the data has gaps or obvious errors, list them at the end
  instead of guessing.

Never invent numbers. If a figure isn't in the data, say so.

Now a chat in this Project only needs: "Here's this week's file. Write the report."

Tips

Make one Project per recurring job or area, not per one-off question. Keep knowledge files tidy and current: an old version of a template quietly produces old-format output. On Team plans you can share a Project so colleagues get the same setup.

Chapter 6 · The app toolkit

Artifacts

Artifactstandalone output · all plans

A piece of work Claude makes that lives outside the chat as its own page: a document, a slide deck, a design, a chart, a dashboard, or a small working app. You can keep editing it, share it with others, and reopen it later from the Artifacts tab in the sidebar.

Turn artifacts on in Settings → Capabilities (the same switch as code execution and file creation). After that, Claude makes an artifact whenever the result is something you'll keep or reuse. You can also just ask: "make this an artifact".

Artifact types

Docs

Documents you and your team edit together with Claude. Export to Word, PDF or Markdown.

Slides

Decks you can present, or export to PowerPoint or PDF.

Design

Mockups, prototypes and one-page layouts.

Dashboards beta

Charts built from connected data. Pro and above.

Motion beta

Animated explainers you can export as MP4. Team and Enterprise.

Custom pages and apps

Calculators, trackers, quizzes, interactive guides like this one.

Three things that make artifacts more than pages

  • Sharing. Artifacts start private. You decide who can open them, and you can share the link with your team.
  • AI-powered artifacts. An artifact can call Claude itself, which makes it a small app. Each person who uses it signs in with their own account, and the usage counts against their plan, not yours.
  • Saved data. An artifact can save data per person or shared across everyone, up to 20 MB of text. This needs a paid plan. A sign-up sheet or team tracker keeps its entries between visits.
Example

From report to tool

Prompt
Turn this week's TAT data into an interactive dashboard artifact:
- a bar chart of average TAT per gate, with the target as a line
- a filter for vehicle type (inbound / outbound / tanker)
- a table of the 10 slowest trucks, sortable by any column
Mobile-friendly. Use red/amber/green for the status rules in the
project instructions.

Then share the link with the plant managers. Next week, ask Claude to update the same artifact with the new file, so the link stays the same.

Tips

To change part of an artifact, highlight the text and choose Edit with Claude, instead of asking it to regenerate everything. Before typing anything sensitive into a shared artifact, check whether it uses shared storage, which everyone with the link can see.

Chapter 7 · The app toolkit

Files, file creation and code execution

Claude can read what you upload: PDFs, Word files, spreadsheets, CSVs, images, screenshots and slides. With code execution and file creation turned on (Settings → Capabilities, all plans), Claude also gets a private computer in the cloud. There it can run real code on your data and give you back real files: Excel workbooks with formulas, PowerPoint decks, Word documents, PDFs and charts.

Analysis that's actually computed

Totals, averages and trends are calculated by code, not estimated. That makes them far more reliable on big tables.

Files you can download

Ask for "an .xlsx with a pivot tab and a chart" and you get the file, not instructions for making it.

Clean-up jobs

Merge files, fix dates, remove duplicates, split columns, reshape a messy export.

Example

Messy export in, clean workbook out

Prompt (with gate_log_week41.csv attached)
This is raw gate-in/gate-out data for week 41.
1. Clean it: fix the mixed date formats, drop exact duplicate rows,
   and flag trucks with gate-out before gate-in (don't delete them).
2. Calculate TAT in minutes per truck.
3. Give me an Excel file with three sheets:
   "Clean data", "Summary by gate" (avg, median, 90th percentile, count),
   and "Issues" (every row you flagged and why).
4. Add a bar chart of average TAT by gate on the Summary sheet.
Tell me how many rows you removed or flagged.
Check the numbers

Code is accurate, but only if it reads the data the way you meant. Ask Claude to state its assumptions ("I treated blank gate-out as still inside the plant"), and spot-check two or three rows yourself.

A good Research request

Prompt (Research on)
Research: ways mid-size manufacturing plants in India have cut truck
turnaround time at the gate in the last 3 years.

I need:
- 5-8 concrete interventions (e.g. slot booking, RFID gates, e-seals),

Say what kind of sources you trust and what form you want the answer in. Open two or three of the cited links for any figure you plan to repeat. Search results can be wrong, and Claude can misread them.

Memory and personalization

Four settings shape how Claude treats you in every chat. Set them up once, and you stop repeating yourself.

SettingWhat it doesWhere
Instructions for ClaudeStanding information about you and how you like answers. Applies to every chat.Settings → profile / personalization

Example

Good account-wide instructions

Instructions for Claude
About me: I work in requirements and planning at a manufacturing
company. I'm not a developer: explain technical things by what they
mean for the business, not by syntax.

How I like answers:
- Lead with the answer or recommendation, then the reasoning.
- Use tables for comparisons.
- Plain English, short sentences. UK/Indian spelling.
- If my request is ambiguous, ask one short question before a long job.
- Say clearly when you're unsure or when something needs checking.

These are about you. Rules for one job (like the TAT report format) belong in that job's Project or skill.

Incognito chats

Click the ghost icon to start an incognito chat (all plans). It isn't saved to your history and isn't used for memory. Use it for one-off sensitive topics, or when you want an answer that isn't shaped by your past chats. On Team and Enterprise plans, incognito chats can still appear in your organization's data exports.

Tip

Every month or so, open Settings → Memory and read what Claude has stored. Delete anything wrong or out of date. A wrong memory affects every chat until you remove it.

Chapter 10 · The app toolkit

Connectors

Connectorlink to another app · built on MCP

A link that lets Claude read from, and sometimes act in, another app: Google Drive, Gmail, Calendar, Microsoft 365, Slack, GitHub, Notion, Salesforce and many more. Connectors are built on MCP (the Model Context Protocol), so any company can publish one.

Without connectors, you copy and paste. With them, Claude fetches the latest version itself: "summarise the TAT emails from transporters this week" or "find the gate-SOP document in Drive and check our report against it".

How to add one

  1. Open Settings → Connectors (or the tools menu in the chat box) and browse the directory.
  2. Click Connect and sign in to that app. You approve what Claude may access.
  3. In a chat, use the tools menu to switch connectors on or off for that chat.
  4. For an app that isn't listed, add a custom connector with the app's remote MCP address (your IT team may provide one).
Example

Connectors working together

Prompt (Gmail, Drive and Calendar connected)
Before my 3pm logistics review today:
1. Check my calendar for who's attending.
2. Find emails from the last 7 days about gate delays or truck queues.
3. Open "Gate SOP v4" in Drive.
Give me a one-page brief: the main issues raised, who raised them,
and which SOP steps they relate to. Suggest 3 questions to ask.
Only connect what you need

Connectors that can write (send email, create files, edit calendars) can make real changes. Claude asks before taking actions, so read those prompts before you approve them. Turn off connectors a chat doesn't need. They take up context and invite mistakes. Your company's admin may control which connectors are allowed.

Chapter 11 · The app toolkit

Skills

Skillpackaged know-how · all plans (needs code execution)

A folder of instructions, and optionally templates and scripts, that teaches Claude how to do one specific job. Claude loads a skill automatically when your request matches it, so you don't have to paste the instructions in.

A Project gives Claude context for one area. A skill teaches Claude a method it can use anywhere: in any chat, in Cowork, in Claude Code and in the Office add-ins. Anthropic ships built-in skills, for example for creating Word, Excel, PowerPoint and PDF files, and you can add your own. Skills follow an open standard, so the same skill works across Claude's surfaces.

What a skill looks like

A skill is a folder with a SKILL.md file. The short description at the top tells Claude when to use it. The rest tells Claude how. Only the description is always loaded, and the full body loads only when the skill is used, so skills are cheap to keep around.

Example

A "weekly TAT report" skill

tat-report/SKILL.md
---
name: tat-weekly-report
description: Write the weekly plant truck turnaround-time (TAT) report from a
  gate log file. Use when the user asks for the TAT report, gate performance
  summary, or weekly logistics report.
---

# Weekly TAT report

## Steps
1. Load the gate log. Calculate TAT (gate-out minus gate-in) in minutes.
2. Compare each gate with `targets.csv` in this folder.
3. Status: red if more than 15% over target, amber 5-15%, green otherwise.
4. Fill `template.docx` in this folder. Keep its headings.
5. Add one bar chart: average TAT by gate, with the target as a line.

## Rules
- Start with a 3-line summary for managers reading on a phone.
- Never fill gaps with guesses. List data problems in an "Issues" section.
- Round minutes to whole numbers.

Zip the folder (with targets.csv and template.docx inside) and upload it at Customize → Skills → + → Upload a skill. Now "do the TAT report" works in any chat. On Team and Enterprise you can share it with the whole organization.

Fastest way to make a skill

After a chat where you and Claude finally got a process right, say: "Turn what we just did into a skill I can reuse." Claude writes the SKILL.md for you. Read it, fix anything wrong, and upload it.

Chapter 12 · The app toolkit

Cowork

Coworkdesktop, web and mobile agent · Pro and above

An agent version of Claude for knowledge work. You describe an outcome, and Cowork plans the steps and carries them out on its own: reading and writing files in folders you give it, using your connectors and skills, and reporting back when it's done.

Chat is a conversation, where you stay in the loop for every step. Cowork is delegation: you hand over a task and come back to a result. It is available in the desktop app (Mac and Windows) and on web and mobile, where you can also check on tasks from your phone. Anthropic is merging chat and Cowork into one experience, so you may see them side by side.

What it's good at

  • Sorting, renaming and organizing a folder of files
  • Turning a pile of documents (receipts, PDFs, notes) into one spreadsheet or report
  • Multi-step research that ends in a finished file
  • Scheduled tasks: run the same job every morning, weekly, or monthly
  • Using plugins from the Cowork plugin marketplace that bundle skills and connectors for a role, such as finance or sales
Example

A scheduled Monday report

Cowork task
Every Monday at 08:00:
1. Look in the folder "Plant/Gate logs" for the newest CSV.
2. Use the tat-weekly-report skill to produce this week's report
   and save it to "Plant/Reports" as TAT-week-<number>.docx.
3. Draft (don't send) an email to the plant managers group with the
   3-line summary in the body and the report attached.
If the newest file is older than 7 days, stop and tell me instead.
Give it the smallest access that works

Grant Cowork only the folders it needs. Ask it to draft rather than send until you trust a workflow. Agent tasks use your allowance faster than chat because they take many steps.

Chapter 13 · The app toolkit

Claude in Chrome, Office and Slack

These put Claude inside tools you already use, so you don't have to move work in and out of a chat window.

Claude in Chrome paid plans

A Chrome extension with a side panel. Claude can read the page, click, fill in forms and move between tabs. Since August 2026 the side panel runs as a Cowork session, so your skills, connectors and history come with you. Use it for websites that have no connector, such as a transporter's portal you check every day.

Use carefully

Anthropic itself describes browser control as still risky. A web page can contain hidden text that tries to trick an AI into doing something you didn't ask for. Start on low-stakes sites, watch what it does, and don't let it handle payments or passwords. It works in Chrome on desktop only, not in other browsers.

Office add-ins Pro and above

  • Excel: explains formulas, traces errors, builds models and pivot tables, and edits cells while showing you what changed.
  • PowerPoint: builds and restyles slides using your company template.
  • Excel and PowerPoint share conversation context and can use your skills. Anthropic also offers Claude for other Microsoft 365 apps. Check the Microsoft AppSource store for what your account can install.
Tip for Excel

Before you let Claude edit a workbook, ask it to explain how the existing formulas work. You'll catch misunderstandings before they turn into changes.

Claude in Slack Team and Enterprise

Tag @Claude in a channel or thread to hand it work, such as "summarise this thread and draft the decision note". It can follow up later on its own, and admins choose which channels and tools it can use. The Slack connector (Chapter 10) works the other way round: it lets Claude read Slack from a chat in the Claude app.

Chapter 15 · Prompting well

Anatomy of a good prompt

Anthropic's own advice is to treat Claude like a brilliant new colleague who knows nothing about your situation. Their test: if a capable colleague with no background would be confused by your request, Claude will be too. Most weak answers come from missing context, not from a weak model.

Example

Weak prompt vs strong prompt

Weak

"Analyse this TAT data."

Claude has to guess who it's for, what "analyse" means, what matters, and how long the answer should be. You get a generic summary.

Strong

"I'm presenting to plant managers on Friday. They're deciding whether to build a 4th gate. Using the attached week-41 log and targets, tell me which gates are over target and by how much, and whether the data supports a 4th gate. Start with a 3-line answer, then a table by gate. If the data can't answer the question, tell me what's missing."

Don't over-engineer it

A clear paragraph written the way you'd brief a colleague beats a long template. Add structure only when the task is long or has many parts.

Chapter 16 · Prompting well

Ten techniques that work

These come from Anthropic's prompting guides, plus what works in daily use.

1. Explain why, not just what

"Keep it under 150 words because managers read it on their phones" works better than "under 150 words". When Claude knows the reason, it applies the rule sensibly in cases you didn't think of.

2. Say what to do, not what to avoid

"Write in flowing paragraphs" works better than "don't use bullet points". Positive instructions are clearer.

3. Show an example

One good example of the output you want is often worth a page of description. For consistent results, give 3–5 varied examples. Wrap them in tags so Claude knows they're examples, not part of the task.

4. Use tags to separate the parts of a long prompt

Prompt with tags
<context>
Weekly TAT report for plant managers. Targets: inbound 90 min, outbound 120 min.
</context>

<data>
[paste the table here]
</data>

<example>
Gate 2 inbound averaged 112 min (target 90, +24%, RED). Main cause: weighbridge downtime Tue-Wed.
</example>

<instructions>
Write one line like the example for each gate and vehicle type.
</instructions>

5. Put long documents first, questions last

When you paste or attach long material, put your question after it. Claude answers better when the question comes at the end.

6. Give Claude permission to say "I don't know"

Add: "If the documents don't answer this, say so rather than guessing." This one line cuts down on made-up answers more than anything else.

7. Ask for quotes before conclusions

For questions about long documents: "First quote the relevant passages, then answer using only those quotes." You can check the quotes, and Claude stays tied to the source.

8. Let Claude ask you questions first

For bigger jobs, say: "Before you start, ask me up to 5 questions about anything unclear." Five minutes of questions saves several rounds of revision.

9. Break big jobs into steps

Instead of "write the whole business case", go in stages: outline → agree the outline → draft each section → review. Each step is easier to check, and mistakes don't pile up.

10. Iterate in place, with specifics

"Better" doesn't help. "Shorter by half, more direct, and lead with the cost figure" does. If a reply goes badly wrong, edit your original message and resend it, instead of arguing over several turns. The bad answer then stops cluttering the conversation.

Example

Techniques 6, 7 and 8 together

Prompt (with a 60-page transport contract attached)
I need to know our rights if the transporter's trucks wait more than
4 hours at our gate (detention charges).

Before you answer, ask me any questions you need, up to 3.

Then: quote the exact clauses that deal with waiting time, detention
or demurrage, with clause numbers. After the quotes, explain in plain
English what we owe and when. If the contract doesn't cover something,
say "not covered" rather than assuming.
Chapter 17 · Prompting well

Prompt patterns you can copy

Reusable shapes for common jobs. Replace the parts in [brackets].

The interviewer: when you don't know what you need yet

Prompt
I want to [write a requirements document for a truck slot-booking system].
Interview me one question at a time until you have what you need.
Then summarise what you've understood and wait for my OK before writing.

The critic: stress-test your own work

Prompt
Here is my [proposal]. Act as a sceptical [CFO] reviewing it.
List the 5 strongest objections, ranked by how likely they are to sink it.
For each, suggest how I could address it. Be direct; don't soften it.

The options table: decisions

Prompt
I need to decide between [option A, B, C] for [goal].
Compare them in a table on: cost, time to implement, risk, effort for
my team, and reversibility. Then give your recommendation and the one
thing that would change your mind.

The translator: same content, new audience

Prompt
Rewrite this [technical vendor note] for [plant shift supervisors].
They care about [what changes on the floor and when]. Keep every fact;
drop the jargon. Max [120] words.

The extractor: messy text into structured data

Prompt
From these [meeting notes / emails], extract every action item as a table:
owner | action | due date | source quote.
If an owner or date isn't stated, write "unclear" — don't guess.

The teacher: learn something new

Prompt
Teach me [queueing theory basics] as it applies to [truck gates].
Start with the simplest idea and an everyday example. After each idea,
ask me one question to check I've understood before moving on.

The handover: before a chat gets too long

Prompt
Summarise this conversation as a handover note for a fresh chat:
the goal, decisions made, the current draft or state, open questions,
and the next step. Make it self-contained.
Example

Chaining patterns into a workflow

For a slot-booking proposal: Interviewer (gather requirements) → Research (what other plants did) → Options table (choose an approach) → draft as a Docs artifact → Critic (CFO review) → revise → Translator (a short version for supervisors). That's seven small, checkable steps instead of one giant prompt.

Chapter 18 · Prompting well

Working in long conversations

Context windowClaude's working memory for one chat

Everything Claude can "see" at once: your instructions, the files, and every message so far. It is large, but not unlimited. Every new reply re-reads the whole conversation, so long chats are slower, cost more of your allowance, and can drift.

Habits

  • One topic per chat. Start a new chat when the subject changes. Projects and memory carry the background over.
  • Edit instead of correcting. Fix the original prompt and resend it, so failed attempts don't pile up.
  • Hand over when a chat gets long. Use the handover pattern (Chapter 17) and paste the note into a fresh chat.
  • Attach only what's relevant. Ten pages that matter beat 200 pages of "just in case".
Example

Signs it's time for a fresh chat

  • Claude forgets a rule you set at the start
  • It brings back something you already rejected
  • Replies are getting slow
  • You've changed topic twice
  • You see a message that the chat is long, or that your limit is close

A first session that works

Chapter 23 · Working efficiently

Make your usage last

Usage depends on how much Claude has to read and think about, not on how many messages you send. These habits stretch any plan.

  1. Start new chats often. Long chats re-read everything on every reply. This is the biggest single saving.
  2. Use the smallest model that does the job well. Sonnet for most work, Haiku for simple jobs, Opus or Fable when you really need them.
  3. Keep effort at the default unless the answer is clearly too shallow.
  4. Put reusable context in Projects and skills, instead of pasting it into every chat.
  5. Attach only what's relevant. Trim big PDFs to the pages you need.
  6. Turn off unused connectors and tools for the chat.
  7. Batch related questions into one well-structured message instead of five quick ones.
  8. Edit and resend instead of piling corrections on top of a bad answer.
  9. Be specific up front. One clear prompt costs less than three rounds of "not quite".
  10. Save Research and agent tasks for jobs that need them. They are the heaviest features.
Hit the limit?

The 5-hour window refills on a rolling basis, so a break often solves it. On Pro and above you can turn on extra usage in settings, paid at standard rates, so important work isn't blocked.

Chapter 24 · Working efficiently

Workflow recipes

Complete workflows that combine several features. Adapt them to your own work.

Recipe 1

Requirements document from scattered inputs

  1. Create a Project "Slot booking". Upload meeting notes, emails and the current process map.
  2. Chat: use the interviewer pattern to fill the gaps.
  3. Ask: "Draft a requirements document as a Docs artifact: problem, goals, users, user stories, acceptance criteria, out-of-scope, open questions."
  4. Use the critic pattern as an operations head and as an IT head. Revise.
  5. Share the Doc with stakeholders and collect their comments. Ask Claude to work through the comments.
Recipe 2

Meeting → actions → follow-up

  1. Record or transcribe the meeting, or dictate your notes on mobile right after.
  2. Use the extractor pattern for an owner/action/date table.
  3. With the Gmail connector: "Draft a follow-up email to the attendees with the decisions and the action table."
  4. With the Calendar connector: "Suggest a 30-minute check-in next week when all owners are free."
Recipe 3

Data question → evidence → deck

  1. Upload three months of gate logs. Ask Claude to compute the trends with code and list its assumptions.
  2. Opus, high effort: "Test these three explanations for the TAT rise against the data. Which does the evidence support?"
  3. "Make a 6-slide deck (Slides artifact) for the plant head: problem, evidence, cause, options, recommendation, ask."
  4. Export to PowerPoint and polish it in Claude for PowerPoint with the company template.
Recipe 4

Turn a repeated chore into an automation

  1. Do the task once in chat, step by step, until the result is right.
  2. "Turn what we just did into a skill." Review it and upload it.
  3. Run it in Cowork a couple of times and check the results.
  4. Schedule it. Keep "draft, don't send" until you've trusted it for a few weeks.
Recipe 5

Build a small internal tool without coding

  1. Prototype it first as an artifact in chat. It's fast, shareable and free to change.
  2. When it needs real users, a database or logins, move to Claude Code: Plan mode → approve → build → test → commit.
  3. Put the house rules in CLAUDE.md, and ask Claude to test in a browser after every change.
Chapter 25 · Working efficiently

Accuracy, privacy and safety

Accuracy

  • Claude can be confidently wrong, especially on exact figures, quotes, dates, citations and recent events. Verify anything you'll act on or repeat.
  • Ask for sources (web search), quotes (documents) or code (calculations). All three can be checked.
  • Tell Claude it may say "I don't know", and ask it to list its assumptions.
  • For important decisions, ask it to argue the other side as well.

Privacy

  • Follow your company's rules on what data may go into AI tools. Team and Enterprise plans have stronger admin, retention and compliance controls.
  • Check your data settings, including whether your chats may be used to improve models, under Settings → Privacy.
  • Use incognito for sensitive one-offs, and review your memory from time to time.
  • Shared artifacts and shared Projects are visible to everyone they're shared with.

Agents and connected tools

  • Give agents the least access that does the job: specific folders, specific connectors.
  • Read approval prompts before you click Allow, especially for sending, deleting, paying or posting.
  • Be careful with untrusted content. Web pages, emails and documents can contain hidden instructions aimed at AI ("prompt injection"). That's a key reason to keep humans approving actions that matter.
  • Prefer "draft" over "send", and test automations on copies of your data.

Chapter 27 · Mastery

Cheat sheet

Context once

Personal instructions = about you. Project = about an area. Skill = a method. Memory = what Claude learned.

Real outputs

Artifacts for pages, docs, decks and apps. File creation for .xlsx, .pptx, .docx and .pdf. Code execution for exact numbers.

Reach

Web search for quick facts. Research for reports. Connectors for your apps. Chrome for websites.

Delegate

Cowork for multi-step work and schedules. Claude Code for software. Slack for team hand-offs.

Prompt

Role, context and why, task, inputs, constraints, format. An example beats a description. "Say if you don't know."

Save usage

New chat per topic. Sonnet by default. Default effort. Attach less. Edit, don't argue.
